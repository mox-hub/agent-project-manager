### 2.3 关键技术发现（影响后续各桶，务必知悉）

**twMerge v3 中 font-size 类会删除其前方的 `leading-*`/`tracking-*` 类**（实测 vitest 环境：`cn("text-sm leading-none …", "text-sm")` → leading-none 被删）。推论：

- 基线含 leading 的组件（Label `leading-none`、CardTitle `leading-normal`），实例裸写 `text-sm`/`text-base` 会**吞掉基线 leading**；
- 因此「实例字号类与基线同值 ⇒ 冗余删除」（通道 b）对这类组件**不成立**——删除会让 leading 复活、行高改变；
- 正确做法 = 立「还原档」（档值就是同字号类，档位与实例 className 处于同一 twMerge 位置 ⇒ 终串一致），本次已按此给 Label/CardTitle 立还原档；
- 无 leading 的基线（Button/TableCell p-2/TableHead text-left）通道 b 删除安全，已终串对比验证。

## 三、等价证明方法摘要

1. **判据**：同一组件「旧形态（基线 + 违规 className）」vs「新形态（props 档位）」渲染后 className 终串做**排序集合对比**（twMerge 已消解同组冲突 ⇒ 集合相同 ⇒ 生效 CSS 规则相同 ⇒ 渲染逐像素等价）。svg 宿主经 `getAttribute("class")` 取值。
2. **通道 a（档平移）**：14 个 vitest 用例覆盖全部批量模式（含组合形态如 `size="2sm" fontSize="xs"`、`padding="p-2" align="right"`），全部通过后才批量套用。
3. **通道 b（冗余删除）**：仅用于「基线同值类且无 leading 吞吐风险」（TableCell p-2、TableHead text-left、Button/Label font-medium、Badge h-5）。

## ③ 下沉（判据 C）等价性论证摘要

- **DialogTitle/SheetTitle「图标+标题行」×9**（template-manager×2 经 CardTitle、linear-sync-log-drawer、readiness-dialog、approval-dialog、batch-update、global-task-export、iteration-detail、linear-projects-table、linear-config-form）：基线 Title 渲染 `<h2>`（`@base-ui/react` DialogTitle 源码 `useRenderElement('h2')`），故下沉容器用 `span`（短语内容，合法于 h2 内）承载 `flex items-center gap-2`。h2 为块级、span(flex) 为块级伸满同行 → 子项（图标/文本）作为 flex item 的排布、gap、换行（flex-wrap 场景）逐项一致。
- **PageBody space-y-6**（template-manager）：PageBody 基线 `flex flex-col` 无 gap；子项包进调用方 `<div className="space-y-6">` 后，PageBody 单一 flex item 拉伸满宽，内部 margin 间距逐项复现。
