# 移动端排期与出口判据

**总纲**：移动端**不另起一条独立跑道**——它与 PC 发版**并行咬合**：①材料与接入点在 **0.8.x 周期内**铺完；②实现从 **0.9 起**分批落地，每批随一次 PC 发版合流。**为什么必须并行**：移动端要复用 server 契约与 `@ordo/shared`，而这些在 PC 侧仍在高速演进——独立跑道必然造成契约漂移与重复适配。并行咬合让移动端**搭 PC 的顺风车**，而非维护一条平行分支。

## 一、阶段总表

| 阶段 | 目标 | 出口判据（**进下一阶段的准入**） | 与 PC 发版关系 |
|---|---|---|---|
| **M0** 材料 + spike | 产出 [README](./README.md) 所列全套材料；跑通技术选型 spike | ①`git ls-files docs/design/mobile` 非空且 12 项材料齐；②`pnpm check:docs-sync` 绿；③[spike 报告](./spike-Expo-RN-报告.md) 给出结论 + 实测数据，判据 1–7 全过（见 [ADR-M-001](./ADR-M-001-移动端技术路线.md) §5）；④ADR-M-001 状态由 Proposed → Accepted | **全程在 0.8.x 周期内**；**不发移动端生产代码** |
| **M1** 工程骨架（0.9 起） | `apps/mobile` 空壳工程落地 + 工程接入点铺完 + `apm-contract` 抽包 + 契约单源化 | ①`apps/mobile` 的 `type-check`/`lint`/`test` 三脚本可跑通（空壳）；②移动端 PR 能触发 `test-mobile` job（**验证非静默跳过**：故意改一行看 CI 真的跑）；③`packages/apm-contract` 抽包完成，`@ordo/shared` 既有 import 全不变；④契约单源化四步完成（生成目标改指 + 删滞后产物 + 改文档表述 + `contract:check` 绿）；⑤登录 → `/auth/me` → 空壳首页链路通 | **接入点改动（CI / 抽包 / 契约）必须随一次 PC 发版合流**——它们触及 CLI/server import 与 `.github/`，单独在移动端分支上做会与 PC 主线冲突 |
| **M2** 一期核心场景 | MVP = `CAP-M-01` + `M-02` + `M-03` + `M-08` 子集 | ①三条真实链路**双端真机**跑通（iOS + Android）：登录/工作区 → 收件箱（推送+角标）→ 决策卡拍板；②后端适配一期项（[后端适配清单](./后端适配清单.md) B1+B2 推送全链）已随 server 发版落地；③红线用例 D7（决策指纹拒批）/ D8（审计缺失不默认通过）通过（[测试策略](./测试策略.md) §三）；④L3 移动端特有断言全绿 | **后端改动（B1/B2）必须随 0.9.x server 发版**——移动端实现前推送全链须已到位 |
| **M3** 打磨与扩展 | `CAP-M-04/05/06/07` 分批；无障碍、离线降级、性能 | ①命中区（≥48）/ 字阶（正文 16、中文 ≥14）/ 安全区 / Dynamic Type 合规（L3 断言 + L4 真机目检）；②EAS 内测包可安装分发，OTA 回滚路径演练过；③增强项（B3–B7）按需补齐 | **与 0.9.x 后续发版咬合**；移动端独立版本号，但契约对应关系逐次在 `CHANGELOG.md` 登记（[发布与分发方案](./发布与分发方案.md) §五） |

## 二、必须在 PC 周期内完成的前置（五项）

这五项**必须在 M0→M1 之间、PC 发版的间隙内**落地。**为什么强调「PC 周期内」**：它们的改动面在 PC 侧（`.github/`、CLI/server import、契约链），越晚做，与 PC 主线的冲突面越大；且**第一项不做，移动端首个 PR 会「全绿但什么都没跑」**。

| # | 前置 | 为什么必须在 PC 周期内 | 出口证据 |
|---|---|---|---|
| 1 | **CI 分类器 + `test-mobile` job** | 分类器不认识 `apps/mobile` → `SOURCES=false` → **门禁全跳过还显示全绿**（静默失效，比红灯更危险）；且 `.github/` 改动会触发全量，趁发版间隙做代价最小 | 故意改一行移动端代码，确认 CI 真的跑起 `test-mobile` |
| 2 | **`apm-contract` 抽包** | 触及 CLI/server 的 import 面；越晚做，PC 侧新代码越多、re-export 迁移面越大 | `@ordo/shared` 既有 import 全绿；`packages/apm-contract` 依赖树无 `node:*` |
| 3 | **server 侧后端适配（B1+B2 推送全链）** | 移动端 M2 实现前推送必须已可用；server 端点需随 server 发版 | `openapi.json` 含 device 端点；推送派发器落地 |
| 4 | **事件网关补转发 `task.assigned` / `mention.created`** | 归 M-06/M-08（增强，非一期阻断），但改动在 `events.gateway.ts` 白名单——随 server 周期做成本最低 | 网关白名单补录，`check:cli-contract` 绿 |
| 5 | **契约单源化 + 删滞后产物** | 删 `packages/ordo-shared/src/generated/api-types.gen.ts`（手工滞后产物）并改 `AGENTS.md`/`architecture.md`「双份」表述——**按不静默覆盖，须在 PR 显式说明「原表述与事实不符」** | 单份生成 + re-export；`contract:check` 绿 |

> 前置 3/4 的**展开与证据**见 [后端适配清单](./后端适配清单.md)；前置 1/2/5 的**逐条改法**见 [工程接入方案](./工程接入方案.md) §三/§四。

## 四、风险与回退点

| 风险 | 触发信号 | 回退点 |
|---|---|---|
| **spike 失败**（Metro 在 pnpm workspace 下打不通，或产物含 Node 内置模块） | 判据 1 不过 | 回炉 [ADR-M-001](./ADR-M-001-移动端技术路线.md)——评估子路径导入/抽包是否能解，或改技术路线；**不得**在 spike 未过的情况下开工 M1 |
| **CI 静默跳过**（分类器漏改） | `test-mobile` 不触发 / PR 全绿但无测试记录 | 前置 1 的出口证据（故意改一行验证）是**强制**项，不得以「看起来绿」代替 |
| **契约漂移**（移动端消费了滞后类型） | `contract:check` 报差异 / 移动端 type-check 引用到旧字段 | 前置 5 未完成前**不得**开工 M1；契约单源化是 M1 的准入条件 |
| **推送全链延期**（B1/B2 未随 server 发版） | `openapi.json` 无 device 端点 | M2 降级：一期先只做前台轮询 + 角标（推送通道后补），但**须登记降级**（不静默把「离桌可用」当成已交付） |
| **规划膨胀**（M 线一次全做） | M2 范围超出一期 MVP 四卡 | 严按一期 MVP 界；M-04/05/06/07 一律进 M3 分批 |

## 五、与 PC 发版的咬合关系（一图）

```
PC 周期:   0.8.x ─────────► 0.9.x ──────────────► 0.9.x 后续
              │               │                      │
移动端:    M0 材料+spike    M1 骨架(前置五项)       M2 一期 ──► M3 打磨
              │               │                      │
            不发生产代码    接入点随 PC 发版      后端适配随 server 发版
```

**纪律**：移动端的每个实现批次**必须**绑定一次 PC 发版——**不允许**移动端在独立的长期分支上漂移（移动端没有独立的 server，契约真相源在 PC 侧）。
