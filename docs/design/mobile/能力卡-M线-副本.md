# 能力卡 M 线（可评审副本）

> **为什么有这份副本**：`docs/01-需求/` 不入 git（无评审、无历史），而移动端材料的可评审性要求在入库处（`docs/design/`）。故 §4.8 的十卡在此展开为可评审版；**任何能力范围变更必须先改 §4.8**（走 `requirement-intake`），再同步本副本。
>
> **通用边界（十卡共享）**：①AI 不得自己生成标准、自己宣称符合、再把自己的结论当独立证据（红线）；②所有判定类页面（M-03/M-05）**移动端只呈现不重算**；③移动端不构造第二真相源，服务端响应为唯一真相。

---

## CAP-M-01 工程底座与认证

- **用户价值**：手机上有一个安全可用的身份入口，并且能确认自己进入了**正确的工作区**（多工作区场景下这是最常见的事故点）。
- **边界（非目标）**：不含任何治理业务页；**工作区管理**（创建/初始化/仓库绑定/备份恢复）不做，只做登录页与「我的」页的**选择器**。
- **依赖**：`CAP-A-01`（身份与令牌）、`CAP-A-26`（登录前工作区选择 + 未认证名单发现）。
- **测试**：`GAP-T-69`（开工时拆细）。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：在手机上登录并确认自己进入了正确的工作区。
  2. **AI 职责**：**无**（纯认证链路）。
  3. **可信依据**：服务端 `/auth/me` 与工作区名单为唯一真相；token 存**系统安全存储**（iOS Keychain / Android Keystore），不落明文。
  4. **人类控制**：登录、登出、切工作区**全由人发起**；无静默身份切换、不自动沿用上一个账号。
  5. **失败与降级**：token 过期 → 显式回登录页；工作区不可达 → 给可读错误与出路，**绝不踢回登录页死循环**（对齐 `CAP-A-25` 的教训）。
  6. **跨模块闭环**：输入 = 凭证；输出 = 带 `x-workspace-id` 的会话，供 M-02…M-08 全体消费。

## CAP-M-02 通知收件箱与推送

- **用户价值**：人不在电脑前也能「被告知」，并能对通知做基本处置（已读 / 归档 / 点开详情）。
- **边界（非目标）**：不含通知偏好的**全量编辑**（移动端偏好页只读，编辑回桌面）；分类持久化策略见下 R6。
- **依赖**：`notification`（既有模块）、`CAP-A-19`（执行失败/审批挂起的通知供给侧）。
- **测试**：`GAP-T-69`。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：离桌时及时知道「有人要我处理什么」。
  2. **AI 职责**：**无新增职责**（推送是确定性转发）；可选的「AI 摘要」明确后置，不进一期。
  3. **可信依据**：服务端通知记录为真相；**推送只作触达**，不携带实体内容（避免载荷与服务端分叉）。
  4. **人类控制**：已读/归档为显式动作；**清空未读需二次确认**。
  5. **失败与降级**：推送未授权或失败 → 回落轮询；列表拉取失败 → 显错误可重试；不做静默丢弃。
  6. **跨模块闭环**：输入 = notification 事件（含 execution 失败、审批挂起）；输出 = 用户处置动作回写通知状态。
- **R6（风险）**：通知的未读/分类若只在本地存会与服务端单一口径分叉 → **服务端通知记录为唯一真相，本地只做展示态缓存**。

## CAP-M-03 决策卡拍板 ★楔子

- **用户价值**：**单手完成审批/冲突/提案的通过或驳回（含理由）**——这是离桌场景里价值密度最高的动作（不处理就卡住别人）。
- **边界（非目标）**：仅 `approval` / `contract_conflict` / `proposal` 三类；`adjust` / `alternative`（**无写路径**）不做，移动端只读并提示回桌面；`acceptance` 类归 `CAP-M-05`。
- **依赖**：`CAP-C-04`（决策卡与批准指纹）、`CAP-B-07`（信任等级——影响谁能批）。
- **测试**：`GAP-T-69`。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：在离开电脑时把「卡住别人的决定」当场做掉。
  2. **AI 职责**：判定倾向**仅作参考呈现**（`aiJudge` 既有数据），**不替人拍板、不预选**（红线落点）。
  3. **可信依据**：决策卡自带证据链与指纹（`approvedFingerprint`），移动端**原样呈现不改写**。
  4. **人类控制**：按钮即人令，理由可选填；**「人确认」不成为责任转移**——界面不得暗示「AI 已判断所以直接通过」。
  5. **失败与降级**：冲突/失效指纹 → **拒批**并提示回桌面复核；网络失败 → **不乐观置态**（禁止先本地移除再报错）。
  6. **跨模块闭环**：输入 = pending decisions；输出 = `resolve` 动作回流执行域 / 契约域。

## CAP-M-04 执行盯盘

- **用户价值**：盯执行八态、看事件流，失败时能按诊断重试或取消——「AI 同事还在正常干活吗」的即时答案。
- **边界（非目标）**：不含**发起执行**、不含执行隔离配置（回桌面）。
- **依赖**：`CAP-B-03`（执行重派与状态机）、`CAP-A-19`（失败诊断与重试）、`CAP-A-04`（工单执行契约）。
- **测试**：`GAP-T-69`。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：离桌时确认执行健康，且失败能救。
  2. **AI 职责**：失败诊断文本**既有**（failure-diagnosis），移动端只读消费。
  3. **可信依据**：执行事件流与状态机为真相，**不本地推算状态**。
  4. **人类控制**：重试/取消为显式人令，取消需确认。
  5. **失败与降级**：断线显示最后同步时间，**不伪装实时**；重试失败诚实报错。
  6. **跨模块闭环**：输入 = execution 事件；输出 = 重试/取消动作，可选评论回流活动流。

## CAP-M-05 验收与证据查看

- **用户价值**：离桌时完成「验收放行」这一收口动作——看标准（含 revision/有效期）、证据、AI 概率，可 accept / reject / waive。
- **边界（非目标）**：不含 criteria CRUD、不含 checklist 管理面（回桌面）。
- **依赖**：`CAP-B-01`（标准版本化与证据失效）、`CAP-B-02`（完整性审计）。
- **测试**：`GAP-T-69`。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：离桌时完成验收放行。
  2. **AI 职责**：提供判定概率与**缺口账**作参考（advisory），**不宣称合格**（红线落点）。
  3. **可信依据**：标准版本快照 + 证据链 + 审计结论；移动端**只呈现不重算**。
  4. **人类控制**：放行/驳回/豁免皆人令；**豁免必填理由**。
  5. **失败与降级**：证据详情加载失败可重试；**审计报告缺失 → 显「未审计」且不得默认通过**。
  6. **跨模块闭环**：输入 = acceptance 详情与证据；输出 = 判定动作回流验收域与通知。

## CAP-M-06 工单详情·评论·@AI

- **用户价值**：看工单全貌、发评论、@AI 同事、指派 agent——离桌时补一句上下文或把活派出去。
- **边界（非目标）**：不含富文本深编辑、不含依赖编排画布。
- **依赖**：`CAP-A-06`（工单详情与文档关联）、`CAP-C-01`（AI 同事会话）。
- **测试**：`GAP-T-69`。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：离桌时补上下文 / 催进度 / 把活派给 AI 同事。
  2. **AI 职责**：被 @ 后按**既有会话链**响应（不新增能力）。
  3. **可信依据**：工单与评论以服务端为真相；指派走**既有信任门禁**（`CAP-B-07`）。
  4. **人类控制**：评论发送、指派均为显式动作。
  5. **失败与降级**：发送失败保留草稿可重试；附件不支持则明示。
  6. **跨模块闭环**：输入 = issue 详情；输出 = 评论/指派事件回流活动流。

## CAP-M-07 发起需求

- **用户价值**：灵感来时随手把想法落成 issue 草稿（标题 + 描述 + 项目 + 类型），不丢。
- **边界（非目标）**：不含访谈 grill 全流程（回桌面走 `CAP-P-01`）。
- **依赖**：`CAP-P-01`（需求承接管道）、`CAP-C-08`（AI 表面/静默场景）。
- **测试**：`GAP-T-69`。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：随手记成可追踪的工单。
  2. **AI 职责**：可选一键补全描述/验收标准（复用既有 `acceptance-draft` 静默场景），**人可不用**。
  3. **可信依据**：落库走既有 issue 创建链与验收契约（不另起端点）。
  4. **人类控制**：草稿由人确认后创建，AI 补全内容可编辑。
  5. **失败与降级**：离线**不静默丢**——草稿本地暂存并提示联网重试。
  6. **跨模块闭环**：输入 = 人的原始想法；输出 = issue 实体并入管道 ①。

## CAP-M-08 实时通道·深链·徽标

- **用户价值**：「有动静」即时可见（事件实时到达、点通知直达卡片、Tab 角标），不必手动刷新。
- **边界（非目标）**：不含**离线写队列**（一期只读缓存）。
- **依赖**：事件网关（`gateways/events.gateway` 命名空间 `/events`）、`domain-events`（事件类型单一来源）。
- **测试**：`GAP-T-69`。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：动态即时可见并可一键直达。
  2. **AI 职责**：**无**（纯事件管道）。
  3. **可信依据**：`DomainEventTypes` 单一来源，移动端**只订阅不另立口径**。
  4. **人类控制**：角标可清、订阅范围可见。
  5. **失败与降级**：后台暂停轮询、回前台重连并补拉、断线显横幅**不伪装在线**。
  6. **跨模块闭环**：输入 = `/events` 事件流；输出 = M-02…M-07 各页刷新与深链跳转。
- **前置缺口（须在 M1 处置）**：事件网关当前**未转发** `task.assigned` / `mention.created`；移动端「被告知」依赖这两类事件，须先补转发（详见 [后端适配清单](./后端适配清单.md)）。

## CAP-M-09 移动设计系统·无障碍·离线降级

- **用户价值**：触控 / 字阶 / 安全区 / 无障碍 / 降级统一底座，供全 M 线页消费——「点得着、看得清、转得了」。
- **边界（非目标）**：**不追求与前端 token 数值一致**（只继承**角色语义**：语义色/状态/信任等级口径），RN token 管道独立。
- **依赖**：`CAP-B-09`（设计系统三层分层：raw 原语 / semantic 语义组件 / ui 存量）；前端宪法的角色语义。
- **测试**：`GAP-T-69`。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：任意 M 线页面在真机上可用。
  2. **AI 职责**：**无**（设计底座）。
  3. **可信依据**：`PRINCIPLES-MOBILE.md` 条文 + 移动端 `check-*.mjs` 机器镜像（对标前端 §11.2 效力链）。
  4. **人类控制**：无障碍偏好（字号/减动效）**尊重系统设置**，不覆盖。
  5. **失败与降级**：离线只读缓存 + 显式离线态；写操作需联网。
  6. **跨模块闭环**：输入 = 宪法条文；输出 = 全 M 线组件与闸门。

## CAP-M-10 发布与分发

- **用户价值**：测试人员拿到能装的包、改了能热更（EAS 构建、签名、内测分发、OTA 通道）。
- **边界（非目标）**：不含对外正式上架运营（**一期只内测**）。
- **依赖**：—（新管线）。
- **测试**：`GAP-T-69`。
- **状态**：`planned`。
- **六问**：
  1. **用户任务**：拿到可安装包并接收更新。
  2. **AI 职责**：**无**（工程管线）。
  3. **可信依据**：EAS 构建产物与版本号；**与 PC 发版节奏对齐登记**（见 [排期与出口判据](./排期与出口判据.md)）。
  4. **人类控制**：发版与更新通道开关由人决定。
  5. **失败与降级**：构建失败留日志；OTA 失败可**回滚上一版**。
  6. **跨模块闭环**：输入 = 代码与 M 线材料；输出 = 可安装包与更新通道。
