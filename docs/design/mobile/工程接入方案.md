# 移动端工程接入方案

**总纪律**：下列接入点**必须在 PC 发版周期内完成**——否则移动端首个 PR 会命中一个**静默失效**：CI 分类器不认识 `apps/mobile` → `SOURCES=false` → 门禁全跳过**还显示全绿**。

---

## 一、目录结构（`apps/mobile/`）

```
apps/mobile/
├── app/                        # expo-router 文件式路由（Stack + Tab 分组）
│   ├── (auth)/{login,workspace}.tsx
│   ├── (app)/
│   │   ├── _layout.tsx         # Bottom Tab（收件箱/执行/工单/我的）
│   │   ├── inbox/…
│   │   ├── executions/…
│   │   ├── issues/…
│   │   └── me/…
│   └── _layout.tsx
├── src/
│   ├── modules/                # 按 M 线能力卡分模块（inbox / decisions / executions / issues / acceptance / me）
│   ├── components/             # semantic（语义组件）+ raw（原语）——对标前端 CAP-B-09 三层分层
│   ├── infrastructure/         # api-client / event-client / secure-store / cache 注入层
│   ├── i18n/                   # 复用 en/zh-CN 键，locale 文件独立副本
│   └── theme/                  # RN token 管道（§6.2 的 token 唯一入口）
├── scripts/check-*.mjs         # 本卷的机器执行镜像（见 §五）
├── assets/
├── app.json  eas.json  metro.config.js  tsconfig.json  package.json
```

- **`pnpm-workspace.yaml` 无需改动**——`apps/*` 已自动纳入。
- **`turbo.json` 无需改动**——移动端**不定义 `build`**（原生构建走 EAS，学 `apps/desktop` 先例：desktop 也只有 `type-check`/`lint`/`build:electron`，`build` 不出产物到 `dist/**`），只挂 `type-check` / `lint` / `test`。

## 二、`@apm/shared` 复用：两阶段，最终收敛到 `packages/apm-contract`

### 2.0 根因（已实证）

`packages/apm-shared/src/index.ts` **一次性 re-export 了 Node 专有模块**：

| 导出 | Node 依赖 | 可进 RN？ |
|---|---|---|
| `./config/store` | `fs` / `os` / `path` | ❌ |
| `./cli/*`（adapters / process-runner） | `child_process` | ❌ |
| `./errors` / `./apm-ref` / `./runtime/protocol` / `./events/domain-events` / `./http/apm-client` / `./http/envelope` | 无（纯 TS） | ✅ |

→ **整体 import `@apm/shared` 进 RN 必炸**（RN 无 Node 内置模块）。

### 2.1 spike 期（M0）：子路径导入

用**子路径导入**绕开根 index，零改动快速证伪：

```ts
import { DomainEventTypes } from '@apm/shared/events/domain-events';
import { ApmClient } from '@apm/shared/http/apm-client';
```

**前提**：`@apm/shared` 需暴露 `exports` 子路径映射（若无则补 `package.json`.`exports`）——**这是 spike 判据 1 的一部分**（Metro 打包产物不得含 `fs`/`os`/`path`/`child_process`）。

### 2.2 立项期（M1）：抽 `packages/apm-contract`

**新建纯 RN + web-safe 包**（依赖仅 `axios` + `zod`）：

```
packages/apm-contract/
├── src/
│   ├── generated/api-types.gen.ts   # ★ 契约类型单源生成目标（见 §三）
│   ├── http/apm-client.ts  http/envelope.ts
│   ├── events/domain-events.ts
│   ├── runtime/protocol.ts
│   ├── apm-ref.ts  errors.ts
│   └── index.ts
```

`@apm/shared` 改为**从它 re-export**（CLI/server 既有 import 全部不变）。理由：一次性消灭「RN 误触 Node 依赖」隐患与「子路径靠 dist 镜像」的脆弱约定，并给契约类型一个**单源生成目标**。

**验收**：`@apm/shared` 现有一切 import 不变；`packages/apm-contract` 的依赖树**不含 `node:*`**（用 `knip` + 打包产物扫描双验）。

## 三、契约单源化（必做，独立小 PR）

### 3.1 现状（已实证的偏差）

| 事实 | 证据 |
|---|---|
| 只有**一份**真生成器 | `contract:generate` 输出**前端** `api-types.gen.ts` |
| `packages/apm-shared/src/generated/api-types.gen.ts` 是**手工滞后产物** | 无生成器、无任何 import、行数与前端版不一致（50812 vs 50923） |
| 文档声称「双份生成」 | `AGENTS.md`（L167/L190）与 `architecture.md`（L190）写「双份 `api-types.gen.ts`（前端 + @apm/shared）」——**与事实不符** |

### 3.2 处置

1. `contract:generate` 的**生成目标改指** `packages/apm-contract/src/generated/api-types.gen.ts`；前端那份改为 **re-export**（`export type * from '@apm/contract/generated/api-types'`）。
2. `scripts/contract-check.mjs` **只校验单份**。
3. **删除** `packages/apm-shared/src/generated/api-types.gen.ts`（手工滞后产物）。
4. 修正 `AGENTS.md` L167/L190 与 `architecture.md` L190 的「双份」表述为**真实口径**（单份生成 + re-export）——按「不静默覆盖」，此修正须在 PR 描述中显式说明「原表述与事实不符，非新增偏离」。

**落地时机**：M1，与 `apm-contract` 抽包同 PR（顺序：先抽包 → 再改生成目标 → 再删产物 → 再改文档）。

## 四、接入点逐条（CI / turbo / knip / lint-staged）

### 4.1 `.github/workflows/quality-gate.yml`（最易踩坑，优先做）

分类器新增一行 + 并入 `SOURCES`，并扩 `CONTRACT` 正则：

```diff
  FRONTEND=$(yes_no has '^apps/frontend/')
  SERVER=$(yes_no has '^apps/server/')
  CLI=$(yes_no has '^apps/cli/')
  SHARED=$(yes_no has '^packages/apm-shared/')
+ MOBILE=$(yes_no has '^apps/mobile/')
+ CONTRACT_PKG=$(yes_no has '^packages/apm-contract/')
  GLOBAL=$(yes_no has '^(package\.json|pnpm-workspace\.yaml|pnpm-lock\.yaml|turbo\.json|scripts/|\.github/)')
  CONTRACT=$(yes_no has '^(openapi\.json|apps/server/src/|packages/apm-shared/src/|packages/apm-contract/src/)')

  SOURCES=false
- if [ "$FRONTEND" = true ] || [ "$SERVER" = true ] || [ "$CLI" = true ] || [ "$SHARED" = true ] || [ "$GLOBAL" = true ]; then SOURCES=true; fi
+ if [ "$FRONTEND" = true ] || [ "$SERVER" = true ] || [ "$CLI" = true ] || [ "$SHARED" = true ] || [ "$MOBILE" = true ] || [ "$CONTRACT_PKG" = true ] || [ "$GLOBAL" = true ]; then SOURCES=true; fi
```

新增 `mobile` 输出 + `test-mobile` job：

```yaml
  test-mobile:
    needs: changes
    if: needs.changes.outputs.mobile == 'true'
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: pnpm }
      - run: pnpm install --frozen-lockfile
      - run: pnpm --filter "./apps/mobile" run type-check
      - run: pnpm --filter "./apps/mobile" run lint
      - name: 移动端单测（受影响文件）
        if: needs.changes.outputs.full != 'true'
        run: |
          BASE="origin/${{ github.base_ref }}"
          git fetch --no-tags origin "${{ github.base_ref }}" >/dev/null 2>&1 || true
          pnpm --filter "./apps/mobile" exec vitest run --changed "$BASE"
      - name: 移动端单测（全量）
        if: needs.changes.outputs.full == 'true'
        run: pnpm --filter "./apps/mobile" run test
```

> `test-mobile` **不上 EAS/模拟器**——真机与 e2e 走 M2 起的人工/ nightly 通道（见 [测试策略](./测试策略.md)）。

### 4.2 `turbo.json`

**不改**。移动端不定义 `build`（理由见 §一）。

### 4.3 `knip.json`

新增 workspace entry：

```json
"apps/mobile": { "entry": ["app/**/*.tsx", "src/index.ts"] }
```

`ignore` 已含 `**/generated/**`，覆盖契约产物。新增 `packages/apm-contract` entry：

```json
"packages/apm-contract": { "entry": ["src/index.ts"] }
```

### 4.4 `lint-staged.config.mjs`

新增一条（RN 设计治理脚本按 §五目录，**绝对路径调用**，与前端同款约定）。**注意 lint-staged 的 key 是对象字面量，同 glob 不能写两次**（后者覆盖前者）——故 eslint 与设计脚本**必须合并进同一个函数任务**：

```js
const mobileCheck = (name) =>
  `node "${join(REPO_ROOT, "apps", "mobile", "scripts", name)}"`;

export default {
  // …既有条目…
  'apps/mobile/src/**/*.{ts,tsx}': (files) =>
    [
      `pnpm --filter mobile exec eslint --fix --no-error-on-unmatched-pattern ${files.map((f) => `"${f}"`).join(' ')}`,
      mobileCheck('check-tokens.mjs'),
      mobileCheck('check-spacing.mjs'),
    ].join(' && '),
};
```

> 脚本变更是**全库扫描**语义（不按暂存文件过滤）——与前端 `apps/frontend/src/**` 那条同款（前端实测把四次 `pnpm` 启动换成直接 `node` 后由 7.96s 降到 1.47s，本方案沿用）。

### 4.5 五包口径提醒

新增两个包后，`pnpm -r run type-check` 与全仓 `lint` 会自动覆盖；但 **`api:audit --min=95` 与 `contract:check`** 的口径不变（前者只扫 server 端点，后者单份契约）。**新包不进入 `api:audit`**——它是后端端点覆盖率工具。

## 五、RN 版设计治理脚本（对标前端 10 个 `check-*.mjs` 的效力链位置）

前端宪法的效力链是「宪法 → `apps/frontend/scripts/check-*.mjs` → 代码」。移动端**必须重建这条链**，否则 `PRINCIPLES-MOBILE.md` 的 `[MUST]` 无机器镜像（对照本卷附录 A.2）。

| 脚本（候选） | 强制条文 | 探测方式 |
|---|---|---|
| `check-tokens.mjs` | §6.2 禁裸色值、§6.1 角色语义 | 扫 `src/**` 的 `#hex` / `rgb(` / `hsl(` 字面量 |
| `check-spacing.mjs` | §5.1/§5.2 4pt 基格与档位白名单 | 扫 style 对象的间距数值是否 ∈ 白名单 |
| `check-touch-targets.mjs` | §3.1 命中区 ≥ 48 | 静态启发式（按钮类组件须有 `hitSlop`/`minHeight`）+ `评审` |
| `check-type-scale.mjs` | §4.2 字阶档位、§4.5 字重白名单 | 扫 `fontSize` / `fontWeight` 数值 |
| `check-semantic-status.mjs` | §10.5 状态不靠色单传 | 扫状态组件是否同时含图标/文本 |

**降级口径（诚实登记）**：一期先落 `check-tokens` / `check-spacing` / `check-type-scale` 三个纯静态可判的脚本；`check-touch-targets` / `check-semantic-status` 依赖运行时而**标注 `评审` 强制 + 机器化候选**（对标前端 §11.2 第 3 步），不假装已机器化。

## 六、i18n 与环境配置

- **i18n**：复用 `en` / `zh-CN` 双语键集（文案口径一致），但**locale 文件是独立副本**（移动端有桌面不存在的文案，如推送文案）。**必须**在 CI 加 `check:i18n-sync` 的移动端变体（键集对齐，防新增欠债）。
- **环境**：服务端基址、`x-workspace-id` 注入、`/events` 命名空间——全部经 `src/infrastructure/` 单一入口，**禁止**在页面里直连 `axios`（对标前端 infrastructure 注入层的既有约定）。
- **安全存储**：token 走 `expo-secure-store`（Keychain/Keystore），**禁止** `AsyncStorage` 存 token（§11.5 缓存边界：缓存随登出清空）。

## 七、落地顺序（M1 批）

1. 分类器 + `test-mobile` job（`.github/` 改动会触发全量——趁发版间隙做）。
2. `apps/mobile` 骨架 + `type-check`/`lint`/`test` 三脚本可跑通（空壳工程）。
3. `packages/apm-contract` 抽包 + `@apm/shared` re-export。
4. 契约单源化（生成目标改指 + 删滞后产物 + 改文档表述）。
5. `knip.json` / `lint-staged.config.mjs` 接入。
6. RN 设计治理脚本首批三个。
