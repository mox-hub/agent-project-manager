# APM 移动端设计规范（独立卷）

**版本：v1.0（2026-10-11 初版）** — 移动端建设（`CAP-M-01…M-10`）M0 材料期立卷。本版为**首版**：确立效力链与 13 章条文。条文来源 = 产品定位裁决「伴随式掌上治理台」+ [交互模式-原语映射](./交互模式-原语映射.md) + [页面蓝图](./页面蓝图.md) + [ADR-M-001](./ADR-M-001-移动端技术路线.md)。**条款凡未标注强制方式的，一律为 `评审` 强制**，机器化候选在条文批注登记（对标前端宪法 §11.2 第 3 步）。

**地位**：本文件是 `apps/mobile` 界面设计的**唯一真相源**。其余材料（`README.md`、`页面蓝图.md`、`交互模式-原语映射.md`、各 skill）一律**只引用、不承载**设计规则；任何与本文冲突的表述以其为准，并须在当次 PR 中删除。

**效力链**：本文件 → `apps/mobile/scripts/check-*.mjs`（本文件的机器执行镜像）→ 代码。脚本与本文冲突时，**先修脚本再合代码**。

**版本号规则**：本卷版本号**只在本文件头部声明一处**。其他文档一律写「见 `docs/design/mobile/PRINCIPLES-MOBILE.md`」，**禁止抄写版本号**。

**与前端宪法的边界（原文保留声明）**：`docs/design/PRINCIPLES.md` §15.2「本产品是桌面优先的数据密集型工具，非移动端产品；最低支持宽度 1024px；`sm`/`md` 仅用于窗口缩小场景，**不做手机版适配**」**原文保留，对 `apps/frontend` / `apps/desktop` 继续成立**。移动端是**独立表面**，由本卷管辖——两卷不互相覆盖（按「不静默覆盖」铁律，此边界经用户裁决后落定，见决策日志 ADR-018）。

## §1 适用范围与效力链

**1.1 [MUST] 适用对象**：`apps/mobile/**` 的全部界面代码（含组件库与页面）。后端、CLI、`packages/*` 不在本卷范围。

**1.2 [MUST] 效力链三层**：本卷 → `apps/mobile/scripts/check-*.mjs` → 代码。**新增/修改条文时必须同时回答两个问题**：① 该条由哪个脚本强制？② 若暂无脚本，则标注 `评审` 并在条文批注登记机器化候选。

**1.3 [MUST] 不双写**：本卷**不复制**前端宪法的数值条文。凡继承前端概念（字阶阶梯思想、动效白名单、角色语义），本卷只写「继承什么 + 数值如何重算」，引用处写 `见 docs/design/PRINCIPLES.md §N`。

**1.4 [MUST] 角色语义单一来源**：语义色、状态口径（工单状态 / 执行八态 / 信任等级 / 验收三态）**必须与前端同源**——移动端不得自造映射表；口径变化时两卷同 PR 修订。

**1.5 [SHOULD] Review 基准**：**暗色优先**（继承前端 D9）。暗色为基准设计环境，亮色为派生。

## §2 设备与尺寸基线

**2.1 [MUST] 基准设备**：**手机竖屏**（逻辑宽度 375–430pt）。平板（≥ 600dp）**降级为一个放大的单列**——不设计双栏、不做平板专属布局。

**2.2 [MUST] 安全区**：所有页面必须消费系统安全区（`useSafeAreaInsets`）；**顶部与底部 inset 不得被内容覆盖**。底部 Tab Bar 必须避开 Home Indicator 区域。

**2.3 [MUST] 单位口径**：iOS 用 **pt**、Android 用 **dp**（RN 的 `DensityPixel`/无单位数值即逻辑像素）；**禁止**任何形态的物理像素换算、禁止 `PixelRatio` 手算布局。

**2.4 [MUST] 方向**：锁定**竖屏**（`orientation: portrait`）。横屏不支持（一期）。

**2.5 [SHOULD] 分屏/多窗口**：系统分屏下按「缩窄的竖屏」渲染，不新增断点。

> 对照前端 §15（响应式）：前端基线是 `px` + 1024 最低宽度；本卷**重定义**为 pt/dp + 竖屏单列。

## §3 触控基线

**3.1 [MUST] 最小命中区**：**iOS ≥ 44×44pt，Android ≥ 48×48dp**（取严格者：**统一按 ≥ 48×48 逻辑像素**实现）。视觉元素可小于命中区，但**命中区（`hitSlop` 或 padding）必须达标**。

**3.2 [MUST] 热区外扩**：图标按钮、行内操作、关闭按钮一律用 `hitSlop` 外扩至 3.1 标准；**相邻可点元素之间 ≥ 8pt** 空隙，避免误触。

**3.3 [MUST] 触控反馈**：所有可点元素必须有**按下态**（透明度/底色变化 ≥ 可感知）；**不得**依赖 hover 态（触摸无 hover）。

**3.4 [MUST] 列表行高**：单行列表项**最小高度 56**（单行文本）／**≥ 72**（双行文本）；行内多动作时按 3.2 保证动作间距。

**3.5 [SHOULD] 长按判定**：长按阈值 **400ms**（预览）/ **500ms**（菜单，与前端 AISlot 的 500ms 对齐）；长按期间**不得**触发行点击。长按语义二分见 [原语映射](./交互模式-原语映射.md) C3。

> 对照前端：前端**无**触控命中区条文（鼠标精确命中）——本卷**重定义**。

## §4 字阶

**4.1 [MUST] 阶梯思想继承**：采用**语义化命名、名称与 px 解耦**的阶梯（继承前端 D3 的思想），但**数值按移动端重算**，档位数 ≤ 7（移动端不需要 9 档）。

**4.2 [MUST] 移动端字阶表**：

| 档 | 语义 | 值（逻辑像素） | 典型用途 |
|---|---|---|---|
| `caption` | 辅助 | 12 | 时间戳、次要元信息 |
| `footnote` | 注脚 | 13 | 徽标文字、行内标签 |
| `body-sm` | 小正文 | 14 | 次要正文、列表副标题 |
| `body` | **正文（默认）** | **16** | 主要正文、列表主标题、评论 |
| `title` | 标题 | 20 | 页面标题、卡片标题 |
| `headline` | 大标题 | 24 | 详情页主标题 |
| `display` | 展示 | 32 | 空态主文案、数字指标 |

**4.3 [MUST] 中文最小字号**：**≥ 14**（`body-sm` 及以上）。`caption` / `footnote`（12/13）**仅限非中文**（同前端 D5 精神，数值上调）。

**4.4 [MUST] 行高**：正文行高 = 字号 × 1.5（±0.05）；标题行高 = 字号 × 1.3。紧凑行（列表主标题）不低于 × 1.25。

**4.5 [MUST] 字重**：只留 **400 / 500 / 600**（继承前端 D6）；**禁止** 300/700+。

**4.6 [SHOULD] 字体**：优先**系统字体**（iOS SF / Android Roboto）以获得最佳中文渲染与 Dynamic Type 支持；如需品牌字体，须自托管并**验证中文覆盖**（继承前端「中文用思源黑体」的精神，但移动端默认系统字体）。

> 对照前端 §3（9 档 `text-3xs…2xl`，正文 14–15）：概念**继承**，数值**重定义**（正文上调至 16，档位收敛至 7）。

## §5 间距与网格

**5.1 [MUST] 基格**：**4pt 基格**——所有间距、内边距、尺寸必须为 4 的倍数。

**5.2 [MUST] 间距档位**：仅允许 **4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48**（4 的倍数且 ≤ 48）；**禁止**奇数档与任意值。

**5.3 [MUST] 页边距**：页面内容左右边距 **16**；卡片内边距 **16**（紧凑卡 12）；列表项左右内边距 **16**。

**5.4 [MUST] 圆角**：**卡片 / 弹层 12**、**按钮 / 输入框 8**、**徽标 / 胶囊 = 高度一半**；禁止任意值。**禁止**圆角 ≥ 16 的「大圆角」形态（与前端胶囊例外精神一致：胶囊仅限 chip/toggle）。

**5.5 [SHOULD] 分隔**：优先用**空隙**（≥ 8）而非分隔线；必须用线时 1px 且用边框语义色。

> 对照前端 §4.1（间距奇数档冻结）/§4.5（圆角五档）：概念**继承**（基格 + 档位白名单），数值**重定义**为 4pt 网格。

## §6 色彩

**6.1 [MUST] 角色语义继承**：语义色（成功/警告/危险/信息）、状态色（工单状态/执行八态/信任等级/验收三态）**必须映射到与前端的同一套角色名**，取值由移动端 token 管道提供。

**6.2 [MUST] 语义优先**：代码中**禁止裸色值**（`#RRGGBB`、`rgb()`）——一律经 token（`theme.colors.semantic.*` 或等价结构）。语义组件不得暴露原始色 prop。

**6.3 [MUST] 对比度**：正文文本对背景对比度 **≥ 4.5:1**；大字号（≥ 24 且 600 字重）≥ 3:1；图形/图标（承载信息时）≥ 3:1。

**6.4 [MUST] 主题跟随系统**（M-D13）：消费 `useColorScheme()`；**不提供**独立主题设置页。仅保留 DEV-only 强制暗色开关。

**6.5 [SHOULD] 暗色优先验证**：设计评审以暗色为基准环境（继承前端 D9）。

> 对照前端 §5/§6：**部分继承**——角色语义继承，token 管道与数值**另建**（前端是 CSS 变量 + Tailwind，移动端是 RN style 对象）。

## §7 布局与导航

**7.1 [MUST] 导航骨架**：**Bottom Tab（4 项固定） + Stack push/pop 单列 + Modal/Bottom Sheet 临时层**。Tab 项 = `收件箱 / 执行 / 工单 / 我的`，**不自定义、不隐藏、不超 5 项**。

**7.2 [MUST] 无二级 Tab 嵌套**：Tab 内不得再出现 Tab（含顶部 Tab）。二级层级一律 Stack push。

**7.3 [MUST] 单列**：内容区**永远单列**；**禁止**并排两栏 master-detail（与前端 §20 分栏原语的移动端替代见 [原语映射](./交互模式-原语映射.md) P5）。

**7.4 [MUST] Sheet 高度两档**：Bottom Sheet 仅 `half`（≈50%，可拖至 full）/ `full`（≈90%，顶部留安全区）两档；**禁止**固定像素高度。Sheet 打开时**必须**支持下滑关闭（C2 例外见 §8）。

**7.5 [MUST] Modal 二选一**：表单/确认一律**全屏 Modal** 或 **Bottom Sheet**，**不设宽度档**（前端 §10.8 的 sm/wide 宽度谱系在移动端不适用）。

**7.6 [MUST] 页面骨架**：每页 = 安全区 + 标题区（左返回/右动作）+ 内容区（三态：加载/错误可重试/空态）+ 可选底部动作区。标题区高度自适应（见 §10.3）。

**7.7 [MUST] FAB 位置**：FAB 右下角、距安全区底 ≥ 16、距右 ≥ 16；**不得**遮挡 Tab Bar 与列表末项（列表底部补 72 的滚动留白）。

**7.8 [SHOULD] 手势返回兼容**：Stack 页面**必须**支持系统返回手势与硬件返回键（见 §8.1/C5）。

> 对照前端 §20（布局与组合，容器层九条）与 §15：本卷**重定义**——容器层铁律换成「单列 + Tab + Sheet」。

## §8 手势

**8.1 [MUST] 优先级**：**系统手势 > 应用手势**。iOS 左缘 **24pt** 区域归系统返回；应用内水平手势必须从距左缘 ≥ 24 起生效。

**8.2 [MUST] 行内 swipe**：仅用于列表行的**次要动作**（≤ 3 个），水平位移阈值 **≥ 48**；**滚动中不触发**（正交判定）；左滑默认动作必须与右键菜单的首项一致（口径同源）。

**8.3 [MUST] 下拉刷新**：列表页必须支持；刷新态 ≥ 300ms 可见（避免闪烁）；刷新失败保持旧数据 + Snackbar 提示。

**8.4 [MUST] 长按**：见 §3.5；长按语义**按对象类型二分，同对象只给一种**（列表行→预览；实体卡→菜单），禁止分层长按。

**8.5 [MUST] 冲突裁决**（与 [原语映射](./交互模式-原语映射.md) §二一一对应）：C1 左缘 24pt 归系统；C2 全屏 Sheet 时左缘归系统、半屏 Sheet 下滑关闭生效；C4 竖直/水平手势正交；C5 硬件返回 = 栈 pop，栈底返回 = **确认退出**，Modal 打开时返回 = 关 Modal。

**8.6 [SHOULD] 手势可发现性**：行内 swipe 与长按**必须有非手势的可达替代**（行尾 `…` 按钮）；不得让关键动作只能靠手势触达（无障碍红线）。

## §9 动效

**9.1 [MUST] 时长白名单**：仅 **120 / 180 / 240ms**（继承前端 D12）。短反馈（按下）120；过渡（Sheet/页面）180–240；**禁止** > 300ms 的动效。

**9.2 [MUST] reduce-motion**：**必须**尊重系统「减弱动态效果」设置（`AccessibilityInfo.isReduceMotionEnabled`）；开启时禁用位移/缩放类动效，保留瞬时状态变化。

**9.3 [MUST] 缓动**：默认 `ease-out`（进入）/ `ease-in`（退出）；**禁止**回弹（bounce）类缓动用于功能性动效。

**9.4 [SHOULD] 原生动画优先**：优先用平台原生动画（`Animated` 原生驱动 / `LayoutAnimation`），避免 JS 线程动画导致掉帧。

> 对照前端 §7.1：**概念继承**（时长白名单 + token 命名空间要求的精神），实现换为 RN 动画 API。

---

## §10 无障碍

**10.1 [MUST] Dynamic Type**：支持系统字号放大至**系统上限**；**禁止**禁用字体缩放（`allowFontScaling` 不得置 false）。

**10.2 [MUST] 容器高度自适应**：**禁止**固定高度承载文本（同 [原语映射](./交互模式-原语映射.md) C6）；Tab Bar / 工具栏须在最大字号下仍可用（超限时可截断并以无障碍标签补全语义）。

**10.3 [MUST] 屏幕阅读器**：所有可交互元素必须有**无障碍标签**（`accessibilityLabel`）；装饰性元素标 `accessibilityElementsHidden`；列表项须读出「标题 + 关键状态」。

**10.4 [MUST] 焦点顺序**：屏幕阅读器遍历顺序 = 视觉顺序（遇网格可用 `accessibilityViewIsModal` 收口弹层）。

**10.5 [MUST] 状态不靠色单传**：状态（执行八态/验收三态/信任等级）**不得仅靠颜色**传达——须伴图标或文本（继承前端语义色纪律的精神）。

**10.6 [SHOULD] 触控替代**：§8.6 的非手势替代为无障碍硬要求（手势动作必须另有可达路径）。

**10.7 [SHOULD] 对比度**：见 §6.3；`评审` 时用工具实测，不凭肉眼。

> 对照前端 §8.5（无障碍最低要求）：本卷**重定义**——引入 Dynamic Type / VoiceOver·TalkBack / 触控替代三类移动端特有要求。

## §11 离线与降级

**11.1 [MUST] 一期只读**：离线期**只读缓存**；**禁止**离线写队列（不做「稍后同步」的写操作，避免与服务端真相分叉）。

**11.2 [MUST] 离线态显式**：断网/请求失败必须显示**离线态或错误态**（含「最后同步时间」）；**禁止**用旧数据假装实时。

**11.3 [MUST] 乐观 UI 白名单**：乐观更新**仅限幂等低频动作**——标记已读、归档通知、切换工作区。**禁止**用于：决策拍板（需 `approvedFingerprint` 校验）、验收判定（需审计与证据完整）、评论发送（需确认落库）。

**11.4 [MUST] 冲突与失效**：服务端返回冲突/失效（如决策指纹不符）时，**回滚本地态并显式提示**回桌面复核；**不得**静默覆盖。

**11.5 [SHOULD] 缓存边界**：只缓存已拉取内容（列表页 + 详情），**不做**全库预取；缓存须随登出清空。

## §12 通知与徽标

**12.1 [MUST] 未读口径单一来源**（M-D11）：未读数以服务端 `GET /notifications/unread-count` 为唯一真相；本地缓存仅作展示，**联网后必须校对**。

**12.2 [MUST] 徽标位置**：Tab Bar 项角标（未读总量） + **主屏应用图标角标**（`CAP-M-08`）；两处数值同源。

**12.3 [MUST] 清空需确认**：清空未读/批量已读为破坏性动作，**必须二次确认**（§11.3 的乐观白名单仅覆盖单条已读）。

**12.4 [SHOULD] 分类只读**：通知偏好页移动端**只读**（编辑回桌面）；分类维度沿用服务端口径，不自造。

**12.5 [SHOULD] 触达降级**：推送未授权时，首页显式提示「开启推送」入口（引导至系统设置），**不反复弹窗**。

## §13 Push 与深链

**13.1 [MUST] 推送载荷**：仅 `{ type, id, path }`——**不带实体内容**（避免载荷与服务端真相分叉，同 `CAP-M-02` 六问③）。

**13.2 [MUST] 深链复用 Web 路由**（M-D12）：Universal Links / App Links 的路径**沿用 Web 已有路由**（如 `/app/issues/{id}`），使未安装 App 时落到 Web（完整表面）。映射表见 [页面蓝图](./页面蓝图.md) §三。

**13.3 [MUST] 未登录深链**：先落登录页，认证成功后**恢复原目标路由**（暂存目标 → replace 跳转）；**禁止**深链匿名降级（会暴露实体存在性）。

**13.4 [MUST] 冷启动与热启动一致**：深链在 App 冷启动（`getInitialURL`）与热启动（`addEventListener('url')`）两条路径**行为一致**，须各有测试。

**13.5 [MUST] 无效深链**：目标实体不存在/无权访问 → 落**空态页 + 返回入口**，**不得**白屏或崩溃。

**13.6 [SHOULD] 推送权限时机**：在**首次进入收件箱**（价值可见时）请求权限，不在冷启动立即请求。
