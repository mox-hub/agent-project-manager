# 移动端页面蓝图

**推导来源**：产品定位「伴随式掌上治理台」（只读 + 轻写）+ [交互模式-原语映射](./交互模式-原语映射.md)（单列 / Bottom Tab / 长按 / swipe）。**页面只承载 `CAP-M-01…M-10` 已声明的能力**，不新增能力卡范围外的东西。

---

## 一、导航结构

```
App
├─ (auth)  Stack
│   ├─ /login            登录（含工作区选择器）
│   └─ /workspace        工作区选择（登录前名单；多工作区时）
└─ (app)   Tab（4 项，固定不自定义）
    ├─ 收件箱 Inbox      ← 默认首屏（未读优先）
    ├─ 执行  Executions
    ├─ 工单  Issues
    └─ 我的  Me
    └─ FAB（悬浮，仅 收件箱/工单 页显示）→ 快捷创建
Stack（在 Tab 之上 push，任一 Tab 内可达）
    ├─ /notifications/:id        通知详情（含内嵌决策卡）
    ├─ /decisions/:id            决策卡拍板页（approval / proposal / contract_conflict）
    ├─ /executions/:id           执行详情（八态 + 事件流 + 重试/取消）
    ├─ /issues/:id               工单详情（描述 + 评论 + 指派 + 关联执行）
    ├─ /issues/new               发起需求（草稿表单）
    ├─ /acceptance/:id           验收详情（标准 / 证据 / AI 概率 / 判定）
    ├─ /search                   搜索（实体子集）
    └─ /me/about                 关于（版本 / 工作区 / 登出）
Modal / Bottom Sheet（非导航栈，临时层）
    ├─ 预览 Sheet（长按列表行触发）
    ├─ ActionSheet（行尾 `…` / 长按菜单）
    └─ 确认 Modal（驳回理由 / 清空未读 / 退出确认）
```

**Tab 与页的对应关系**：主入口由 Bottom Tab 承担（原语映射 P3/P8）；侧边栏分组（工作台/管道/协同/系统）**压平为一层**，「我的」Tab 收编设置/工作区/关于。**无二级 Tab 嵌套**（单列纪律）。

## 二、页面清单（数据端点以 `openapi.json` 为准）

> 端点前缀统一为 `/_api`。**加粗**为该页主数据源。

### 2.1 认证面（`CAP-M-01`）

| 页面 | 路由 | 数据端点 | 卡片 |
|---|---|---|---|
| 登录 | `/login` | `POST /auth/login` · `GET /auth/public-config` | M-01 |
| 工作区选择 | `/workspace` | **`GET /workspaces/public`**（开启时列名单；关闭时手动输入） | M-01 |

### 2.2 收件箱 Tab（`CAP-M-02` + `CAP-M-03`）★一期核心

| 页面 | 路由 | 数据端点 | 卡片 |
|---|---|---|---|
| 收件箱列表 | `/inbox` | **`GET /notifications`** · `GET /notifications/unread-count` · `POST /notifications/read`；决策区 **`GET /decisions/pending`** · `GET /execution/approvals/pending` | M-02 / M-03 |
| 通知详情 | `/notifications/:id` | `GET /notifications`（按 id 取）+ 关联实体预览 | M-02 |
| 决策卡拍板 | `/decisions/:id` | **`GET /decisions/pending`**（按 id）→ `POST /decisions/proposals/{id}/resolve`；审批 → **`POST /execution/approvals/{id}/resolve`** | M-03 |

**决策卡三类（M-03 边界）**：`approval` / `contract_conflict` / `proposal`——三者均有写路径（approve / reject + 理由）。**`adjust` / `alternative` 无写路径 → 移动端只读展示并提示回桌面**；`acceptance` 类归 M-05。

### 2.3 执行 Tab（`CAP-M-04`）

| 页面 | 路由 | 数据端点 | 卡片 |
|---|---|---|---|
| 执行列表 | `/executions` | **`GET /execution/runs`**（可按 issue/subject 过滤）· `GET /execution/projects/{projectId}/active` | M-04 |
| 执行详情 | `/executions/:id` | **`GET /execution/runs/{id}`** · `GET /execution/runs/{id}/events` · `/steps` · `/logs`；动作 → `POST /ai/execution-runs/{id}/retry` · `POST /ai/execution-runs/{id}/cancel` | M-04 |

**实时**：详情页订阅 `/events`（socket.io 命名空间 `/events`）的执行族事件；断线时显「最后同步时间」不伪装实时（原语映射 C4/§三 N5）。

### 2.4 工单 Tab（`CAP-M-06` + `CAP-M-07` + `CAP-M-05`）

| 页面 | 路由 | 数据端点 | 卡片 |
|---|---|---|---|
| 工单列表 | `/issues` | **`GET /issues`**（项目筛选 `GET /projects`） | M-06 |
| 工单详情 | `/issues/:id` | **`GET /issues/{id}`** · `GET /issues/{id}/activities` · `GET /activities/comments` · `POST /activities/comments` · `POST /issues/{id}/assign-agent` · `GET /issues/{id}/executions` | M-06 |
| 发起需求 | `/issues/new` | **`POST /projects/{projectId}/issues`**（或 `POST /issues`）· `GET /projects` · `GET /issue-types` | M-07 |
| 验收详情 | `/acceptance/:id` | **`GET /acceptance/{id}`** · `GET /acceptance/{id}/criteria` · `GET /acceptance/criteria/{criteriaId}/evidence` · `GET /acceptance/{id}/audit-report`；判定 → `POST /acceptance/{id}/accept-completion` · `/reject-completion` · `/waive` | M-05 |
| 搜索 | `/search` | `GET /search`（实体子集；无命令面） | M-06 |

**M-05 入口**：验收详情从工单详情 push 进入（`GET /acceptance/issue/{issueId}` 解析出 `acceptanceId`）——**不做独立验收 Tab**（窄屏 Tab 稀缺）。

### 2.5 我的 Tab（`CAP-M-01` + `CAP-M-09`）

| 页面 | 路由 | 数据端点 | 卡片 |
|---|---|---|---|
| 我的 | `/me` | **`GET /auth/me`** · `GET /workspaces/current` | M-01 |
| 工作区切换 | `/me/workspace` | `GET /workspaces/public` · `POST /workspaces/{id}/activate` | M-01 |
| 通知偏好 | `/me/preferences` | `GET /notifications/preferences`（**只读**；编辑回桌面） | M-02 |
| 关于 | `/me/about` | 本地版本 + `POST /auth/logout` | M-10 |

## 三、深链映射表（`CAP-M-08`）

**原则**：**复用 Web 路由路径**，让同一条链接在未安装 App 时落到 Web（Web 是完整表面，体验不降级），安装 App 时被 App Links / Universal Links 截获。

| 分享链接（Web 表面） | 移动端目标路由 | 参数 |
|---|---|---|
| `https://<host>/app/issues/{id}` | `/issues/:id` | `id` |
| `https://<host>/app/executions/{id}` | `/executions/:id` | `id` |
| `https://<host>/app/notifications/{id}` | `/notifications/:id` | `id` |
| `https://<host>/app/acceptance/{id}` | `/acceptance/:id` | `id` |
| 自定义 scheme（内部用） | `apm://issue/{shortId}` · `apm://execution/{id}` · `apm://decision/{id}` · `apm://acceptance/{id}` | 短号 `shortId` 走 `GET /issues/by-short-id/{shortId}` 解析为 `id` |

**未登录时的深链**：先落 `/login`，登录成功后**恢复原目标路由**（把深链目标暂存，完成认证后 replace 跳转）。**不做**深链匿名降级（会暴露实体存在性）。

**推送载荷约定**：推送只带 `{type, id, path}`——**不带实体内容**（避免通知载荷与服务端真相分叉）。点开后按 `path` 走深链并实时拉取（原语映射 §三 N1/N3）。

## 四、数据与状态策略（跨页统一）

| 项 | 裁决 | 理由 |
|---|---|---|
| 真相源 | **服务端唯一真相**；App 内不构造第二口径（通知、状态、信任等级、验收判定一律以服务端响应为准） | 与「单一真相源」铁律一致 |
| 缓存 | TanStack Query（与前端同库）+ **持久化只读缓存**（断网可看已拉取内容） | M-09；只读降级 |
| 乐观 UI | **仅用于幂等低频动作**：标记已读、归档通知、切换工作区。**禁止**用于：决策拍板（需 `approvedFingerprint` 校验）、验收判定（需审计与证据完整） | M-03/M-05 红线 |
| 实时 | `/events` 订阅；**后台暂停、回前台重连并补拉**；断线显横幅 | M-08（原语映射 P7） |
| 分页 | **必须分页**（下拉刷新 + 触底加载）；不做「滚动全量」（桌面 PAGE_SIZE=1000 的形态不迁移） | 原语映射 P15 |
| 离线写 | **不做**（一期）。离线只读；写操作需联网并显式提示 | M-09 边界 |
| 错误态 | 每页三态（加载/错误可重试/空态）——沿用前端 `AsyncState` 语义，不新造口径 | 一致性 |

## 五、一期 MVP 边界（`CAP-M-01 + M-02 + M-03 + M-08 子集`）

**一期上线的页面 = 认证面（2.1）+ 收件箱 Tab（2.2）+ 决策卡拍板 + 深链与徽标。**

- **含**：登录/工作区 → 收件箱（通知 + 决策队列）→ 通知详情 → **决策卡拍板**（三类）→ 推送深链 → 未读角标 → Tab 骨架与「我的」最小项。
- **不含（一期不做）**：执行 Tab（2.3）、工单详情与评论（2.4）、发起需求、验收详情（2.5 全部）。这些页**从 M3 起分批**，其能力已在能力清单 §4.8 登记，非废弃。

**理由**：离桌后不可替代的两个 job 是**被告知**与**做决定**；M-03 三类决策自带 approve/reject + 理由，闭环自洽，不被证据查看链路拖长（与能力清单 §4.8 MVP 说明同源）。
