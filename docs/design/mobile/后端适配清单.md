# 移动端后端适配清单

**分级**：

- **阻断** ＝ 不补则对应能力卡**一期做不了**，必须随 server 发版先落地。
- **增强** ＝ 一期可降级（功能可用但不完整/不经济），可后补。
- **已核无需改** ＝ 本文档已实测确认现有能力够用，**记录在此以免后人重复调研**。

**纪律**：所有新增端点/字段都要走契约链（`openapi.json` → server `contract:export` → 生成类型），**禁手工改生成类型**。

## 二、阻断项展开

### B1 + B2：推送全链（设备注册 + 派发）

**为什么是阻断**：M-02 的价值主张是「人不在电脑前也能**被告知**」。没有推送，App 只能在前台轮询——**离桌场景等于不存在**（App 不在前台就收不到）。这与「伴随式掌上治理台」的定位直接冲突。

**需要补的两半**：

1. **设备注册端点**（App → server）
   - `POST /notifications/devices`：绑定 `{ platform: 'ios'|'android', token, deviceName?, appVersion? }` 到当前用户（+ 工作区口径）。
   - `DELETE /notifications/devices/{id}`：登出/换机时解绑（**登出必须解绑**，否则会给已登出设备推送——隐私红线）。
   - 存表需新增（Prisma migration）：`PushDevice { id, userId, workspaceId, platform, token, createdAt, lastSeenAt }`，`token` 唯一约束（防重复注册）。
2. **派发器**（server → APNs/FCM）
   - 消费既有 `notification.created` 事件（**已在网关转发**，见 §三）→ 查用户偏好渠道（B3）→ 发 APNs/FCM。
   - **失败与降级**：推送失败**不得**影响通知落库（fire-and-forget，同 quick-judge 的既有模式）；无效 token（`Unregistered`/`NotRegistered`）**自动解绑**并记录。
   - 载荷纪律：**仅 `{ type, id, path }`**（`PRINCIPLES-MOBILE.md` §13.1）——不带实体内容。

**归属与排期**：M-02 实现前，B1+B2 必须随 server 先行落地（[排期与出口判据](./排期与出口判据.md) M1/M2 咬合）。

### B3 补充：渠道语义

`channels: string[]` 是**松散字符串数组**（无 `enum`），故加 `push` **不破坏契约**；但需在服务端派发器内**尊重该渠道**（用户关掉 push 则不推）。**若**后续要把渠道收紧为 enum，则属破坏性变更，须走契约评审。

## 三、增强项与「已核无需改」清单

### 3.1 增强项说明

- **B5（事件网关补转发）**：`task.assigned` 与 `mention.created` **都已存在且有发布方**，且两者的下游 `notification.created` **已转发到用户房间**——所以「被告知」链路（一期）**不依赖** B5。B5 的真实价值是**实时更新工单页与成员页**（非通知路径），归 M-06/M-08，可后补。
- **B6（bootstrap 聚合）**：冷启动需串行多次请求，影响首屏 TTI。可选做 `GET /mobile/bootstrap` 返回 `{ me, workspace, unreadCount, pendingDecisions }`。**一期不阻断**（4 个请求可并行发出）。
- **B7（会话策略）**：移动端用户期望「装一次长期不用重登」。现 JWT 7d。选项：①延长有效期（风险：撤销难）；②refresh token；③复用 PAT（`POST /auth/tokens`）——但 PAT 语义面向 CLI，**不建议**直接复用。**结论**：随 M1 单独裁决（属安全决策，不属工程细节）。

### 3.2 已核无需改（实测结论）

| 项 | 结论 | 证据 |
|---|---|---|
| **CSRF** | **无需改** | `apps/server/src/main.ts:81` 明示「disabled for API endpoints」 |
| **CORS / Origin 白名单** | **原生请求无需改** | RN 的网络栈**不施加浏览器同源策略**（无 `Origin` 头也不被拦）；仅 **Expo Web 预览**（调试用）会受白名单约束——调试时把 dev origin 加白名单即可 |
| **通知列表分页** | **无需改** | `notification.service.ts:42-51` 已支持 `page`/`pageSize`（默认 20）+ `status`/`type`/`projectId`/`from`/`to` 过滤（`notification-query.dto.ts`） |
| **决策卡端点** | **无需改** | `GET /decisions/pending` · `GET /execution/approvals/pending` · `POST /decisions/proposals/{id}/resolve` · `POST /execution/approvals/{id}/resolve` 全在 `openapi.json` |
| **执行盯盘端点** | **无需改** | `GET /execution/runs/{id}` + `/events` · `/steps` · `/logs` · `/artifacts`；动作为 `POST /ai/execution-runs/{id}/retry` · `/cancel` |
| **验收判定端点** | **无需改** | `POST /acceptance/{id}/accept-completion` · `/reject-completion` · `/waive`；读 `GET /acceptance/{id}` + `/criteria` + `/audit-report` |
| **评论与指派** | **无需改** | `GET/POST /activities/comments` · `POST /issues/{id}/assign-agent` |
| **短号解析（深链用）** | **无需改** | `GET /issues/by-short-id/{shortId}` |
| **工作区选择/切换** | **无需改** | `GET /workspaces/public` · `POST /workspaces/{id}/activate` · `GET /workspaces/current` |

> **覆盖结论**：除推送全链（B1/B2）外，**一期 MVP 的全部读路径与写路径后端都已具备**——移动端一期的主要工作量在客户端，不是后端。这是本清单最重要的结论（避免把一个客户端项目误排成后端项目）。
