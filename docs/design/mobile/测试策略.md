# 移动端测试策略

**总原则**：移动端的测试**不是**把前端的 1500+ 用例搬一遍。移动端是**薄客户端**——逻辑大多在服务端（已测），移动端要测的是**三类风险**：①**平台特有缺陷**（触控/安全区/字号/手势）；②**契约消费正确性**（不手抄类型、不构造第二真相）；③**降级行为**（离线/断线/权限拒绝/失效指纹）。

---

## 一、测试分层

| 层 | 工具 | 覆盖什么 | 运行位置 | 归属阶段 |
|---|---|---|---|---|
| L1 **逻辑单测** | Vitest（**与全仓同版本 5.0.0**，catalog 锚定） | 纯函数：投影函数、格式化、状态机映射、防抖/节流 | CI（`test-mobile` job） | M1 起 |
| L2 **契约** | `contract:check` + `tsc -b` | 生成的契约类型能被移动端消费且零漂移 | CI | M1 起 |
| L3 **组件** | **RN Testing Library** + Vitest | 语义组件渲染、无障碍标签、三态（加载/错误/空）、**触控命中区断言** | CI（jsdom/node，无模拟器） | M2 起 |
| L4 **真机 e2e** | **Maestro**（声明式、无需编译测试包） | 主链：登录 → 工作区 → 收件箱 → 决策拍板 → 深链跳转 | **不进 CI**；本地 + 定期 | M2 起 |
| L5 **真机矩阵** | 手动 + Maestro | iOS 一机型 + Android 一机型（各 1 台）；系统版本取主流两档 | 本地 | M2 起 |
| L6 **降级流** | L3 + L4 组合 | 见 §三 | CI（L3 部分）+ 本地（L4 部分） | M2 起 |

**CI 边界（明确）**：`test-mobile` job **只跑 L1–L3**——**不上模拟器、不跑 Maestro**（CI 上 iOS 模拟器成本高且不稳定）。L4/L5 走**本地与发版前人工**（见 [发布与分发方案](./发布与分发方案.md) §5 发版前检查单）。

## 二、L3 组件层：移动端特有的断言（前端没有的）

| 断言 | 依据条文 | 说明 |
|---|---|---|
| **触控命中区 ≥ 48** | `PRINCIPLES-MOBILE.md` §3.1 | 对可交互元素断言 `hitSlop`/`minHeight` 生效后的可点区域 |
| **无障碍标签存在** | §10.3 | 每个可交互元素有 `accessibilityLabel`；列表项读出「标题 + 关键状态」 |
| **容器高度自适应** | §10.2 | 放大字号（mock `fontScale`）后不截断/不溢出 |
| **状态不靠色单传** | §10.5 | 状态元素同时含图标或文本 |
| **Sheet/Modal 开合** | §7.4/§7.5 | 半屏/全屏两档、下滑关闭、返回键关 Modal |
| **三态渲染** | §7.6 | 加载 / 错误可重试 / 空态（**每页**都要有，不是可选） |

> **诚实登记**：`fontScale`、`hitSlop` 的精确度量在 jsdom 下无法真实测量——L3 只能做**结构性断言**（属性存在且取值合规），**真实手感必须在 L4/L5 真机上验**。不假装 L3 覆盖了触控体验。

## 三、L6 降级流清单（每项必须有用例）

| # | 场景 | 期望行为 | 依据 |
|---|---|---|---|
| D1 | token 过期 / 401 | 显式回登录页；**不**静默登出丢数据 | M-01 六问⑤ |
| D2 | 工作区不可达 | 可读错误 + 出路；**不**踢回登录页死循环 | M-01 六问⑤（对齐 CAP-A-25 教训） |
| D3 | 断网（前台） | 显式离线态 + 最后同步时间；**不**用旧数据假装实时 | §11.2 |
| D4 | 断网（后台→前台） | 恢复时**重连并补拉** | §11.1 / 原语映射 P7 |
| D5 | 推送权限被拒 | 首页提示入口引导至系统设置；**不反复弹窗** | §12.5 |
| D6 | 推送投递失败 | 回落轮询；通知落库不受影响 | 后端适配清单 B2 |
| D7 | **决策指纹失效/冲突** | **拒批** + 提示回桌面复核；**不乐观置态** | M-03 六问⑤（红线） |
| D8 | 验收**审计报告缺失** | 显「未审计」；**不得默认通过** | M-05 六问⑤（红线） |
| D9 | 无效深链（实体不存在/无权） | 空态页 + 返回入口；**不**白屏/崩溃 | §13.5 |
| D10 | 冷启动深链 vs 热启动深链 | 两条路径**行为一致** | §13.4 |
| D11 | 登出 | 解绑推送设备 + 清空缓存 | §11.5 / B1 |
| D12 | 评论发送失败 | 保留草稿可重试；**不**清空输入 | M-06 六问⑤ |

**D7 / D8 是红线用例**——它们直接对应「AI 不得自己宣称符合、再把自己的结论当独立证据」。**这两条不通过，M-03/M-05 不得置 `done`**。

## 四、双轴质量口径（与需求入口流程一致）

每个 M 线卡开工登记时，测试义务须同时覆盖两轴：

- **工程规则守住**：不越权（移动端不做桌面专属操作）／不误用旧证据（失效指纹不得被接受）／不绕门禁（指派走信任门禁）／状态口径与数据模型一致（不本地推算状态）。
- **AI 是否真帮上忙**：识别信息不足（缺口账可见）／说明依据（判定带 evidence）／接受纠正（人不采纳时不被"劝"回去）——**而非只测「生成了一段文本」**。

## 五、GAP-T-69 拆解方向（开工时逐卡落）

| 卡 | 拆解重点 |
|---|---|
| M-01 | 认证链（登录/工作区/带库头请求）+ D1/D2 |
| M-02 | 通知列表分页与过滤、未读口径校对（§12.1）、D5/D6/D11 |
| M-03 | **决策三类 resolve 成功/失败**、指纹校验、**D7 红线**、理由字段 |
| M-04 | 八态渲染、事件流、重试/取消 + D3/D4 |
| M-05 | 标准版本快照呈现、证据、**D8 红线**、豁免必填理由 |
| M-06 | 评论发送/失败（D12）、@AI、指派走门禁 |
| M-07 | 草稿本地暂存（离线不丢）、AI 补全可编辑 |
| M-08 | 冷/热启动深链一致（D10）、无效深链（D9）、角标同源 |
| M-09 | L3 全部移动端特有断言（命中区/字号/无障碍/安全区） |
| M-10 | 构建产物可安装、OTA 回滚演练 |

## 六、测试资产位置（约定）

```
apps/mobile/
├── src/**/*.test.ts(x)          # L1 逻辑 + L3 组件（Vitest + RN TL）
└── e2e/*.yaml                   # L4 Maestro 流（不进 CI）
```

**命名**：`*.test.tsx` 为组件、`*.test.ts` 为逻辑；Maestro 流按主链命名（`login-inbox-decide.yaml`）。
