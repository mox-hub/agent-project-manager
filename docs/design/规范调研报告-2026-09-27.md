# APM 前端「设计规范 / 组件规范」调研报告

> **范围**：`docs/design/`、`apps/frontend/` 规范文档 + `apps/frontend/src` 实际用法（875 个 TS/TSX + `index.css`）
> **性质**：只读调研，未改任何文件。文中所有数字均为实测。
> **日期**：2026-09-27

---

## 一、摘要：三个结论

**1. 规范不缺，缺的是「单一权威」。**
已有一套相当强的体系：1 部宪法 + 1 份组件清单 + 7 个自动化校验脚本，且 7 个脚本**全部进了 CI**（PR 门禁 `quality-gate.yml` + 每日 `nightly-full-gate`）。

**2. 但存在两份互斥的「最高权威」文档，且都不是事实权威。** 真正的权威链是：

```
check-*.mjs 脚本（事实宪法，CI 一票否决）
    ↑ 被引用
PRINCIPLES.md（宪法 v1.2，自称最高，但不在 git 里）
    → 代码（index.css / presets.ts 已按 PRINCIPLES 改造）
        →  ← 互斥 →  DESIGN.md v2.0（自称最高，status=未批准，但 check-palette 在引用它）
            → apps/frontend/AGENTS.md（2026-08-23 停更，多处已是错误信息）
```

**3. 最大的实际风险：`apps/frontend/AGENTS.md` §3 现在教的是错的东西。**
它把 lint 明令封禁的 px 直读字阶（`text-8/9/13/15/22/28/32`）写成合法能力，把已删除的 `figma` 预设写成默认真相源，引用已删除的 `src/templates/`。**按它写代码会直接挂 CI。**
