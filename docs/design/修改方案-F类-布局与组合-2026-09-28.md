## 二、规则正文（F0–F11）

> 标记约定：`[MUST]` / `[SHOULD]` 沿用宪法口径；每条尾注「强制」= 落地方式：`评审`（人工清单）/ `lint`（可机器化，标注挂靠脚本）/ `实现`（改组件默认值）/ `迁移`（存量清理）。

### F0 界面层级模型 [MUST]

全站界面深度一律按四层理解，任何新界面先对号入座再动手：

| 层 | 名称 | 承载体 | 例 |
|----|------|--------|----|
| L0 | 应用壳 | `shell-layout.tsx`：左栏（w-56/w-16）+ TabBar（h-10）+ 内容画布 | 全局导航、多标签 |
| L1 | 一级页 | 列表母版（F1.1）：PageHeader + ToolbarRow + 列表 | 工单列表、项目列表、工作台 |
| L2 | 二级页 | 详情母版（F1.2）：SubPageToolbar + 主栏 + RightSidebar(360) | 工单详情、验收详情、成员详情 |
| L3 | 三级内容 | **按优先级承载**：详情内 Tabs/内嵌面板 → Sheet → Dialog → 三级路由（最后手段，复用详情母版） | 任务依赖面板、同步日志、绑定配置 |

- **深度纪律** `[MUST]`：路由深度 ≤ 2 级（L1→L2）；L3 优先用浮层/内嵌面板，开新路由须同时满足「内容 ≥ 一个完整工作面」且「需要独立 URL/多标签」——两条不满足就用 Sheet/Dialog。`强制：评审`
- **浮层串行律** `[MUST]`：浮层（Dialog/Sheet/Drawer）相互嵌套禁止（现状 0 违例，升格为铁律）；需要二次确认一律在其上叠加 `AlertDialog`（走 Portal 同层，宪法 §8.4 铁律的具体化）。`强制：lint 候选（Dialog 内 Dialog AST 检测）`

### F1 页面骨架：两级母版 [MUST]

**F1.1 列表母版（L1）**：`PageShell` + `PageHeader` + `ToolbarRow` + `DataList`/`DataBody`。
- PageHeader（sticky `top-0 z-dropdown h-10`）与 ToolbarRow（sticky `top-10`）**纵向堆叠各占一行**，禁合并进一行、禁第三条 sticky 栏。
- 列表主体滚动、头部驻留；行高按 F7.2。

**F1.2 详情母版（L2）**：`SubPageToolbar`（三列 grid：左=返回/开关，中=标题，右=动作，`px-6 py-2`）+ 主栏 + `RightSidebar`（360px，J8 裁决）。
- 主栏宽度按内容形态二选一 `[MUST]`：**文档型详情**（工单/缺陷/验收/成员——单实体阅读流）`max-w-4xl`；**聚合型详情**（项目详情——多卡片仪表盘网格）`max-w-7xl`。`强制：lint 候选（页面文件手写 max-w 检测）`
- 结构自管：详情页是「全高双栏」结构——外层 `overflow-hidden`，主栏 `flex-1 min-w-0 overflow-y-auto` 贴边滚动，属性栏独立滚动；**不走 PageShell 的居中滚动**。

**F1.3 主栏宽度四档总表** `[MUST]`（全站唯一宽度阶梯，容器宽度只许此四档 + full）：

| 档 | max-w | px 值 | 归属 | 典型页面 |
|----|-------|-------|------|---------|
| full | 无 | 100% | 列表母版 full | 工单列表、看板、甘特图 |
| wide | `max-w-7xl` | 1280 | 聚合型详情、仪表盘 | 项目详情（F1.2） |
| standard | `max-w-5xl` | 1024 | 设置/表单/管理页 | 设置中心、核心配置 |
| reading | `max-w-4xl` | 896 | 阅读页、文档型详情 | 文档阅读、工单详情主栏 |

- 落地形态：L1 用 `PageShell variant`（wide 档已裁决补入，J2）；L2 详情页按 F1.2 自管双栏结构。

**F1.4 嵌套治理铁律** `[MUST]`（DESIGN.md §3.4 条文转正 + 机器化）：页面内禁止手写 `mx-auto max-w-*` 重包一层居中容器——宽度一律由母版分发（PageShell variant / F1.2 详情结构）。`强制：lint（新增 check：`*-page.tsx` 根三层内出现 `mx-auto.*max-w-` 即报，白名单=附录登记）`

### F2 标题栏：四种、结构各自固定 [MUST]

标题栏全站只有四种，禁自创第五种；每种的内容槽位与字号固定：

| 种类 | 载体 | 高度/定位 | 标题档 | 槽位结构 |
|------|------|----------|--------|---------|

**F2.5 标题图标：分层规定，不做全站一刀切** `[MUST]`（用户意见 4 的裁决意见）：

### F3 弹窗 [MUST]

### F9 按钮组合 [MUST]

**F9.1 间距唯一律** `[MUST]`：同组相邻按钮 `gap-2`（8px）唯一档——DialogFooter 默认已是（53/67），推广为全站口径；组与组之间 `gap-3` 或视觉分隔。`space-x-*` 全库封禁（0 实例，防回流）。`强制：lint（并入 check-spacing-governance）`

**F9.2 布局三型** `[MUST]`：右对齐型（footer 默认）/ 两端型（`justify-between`）/ 工具栏型（左动作簇，`HeaderActionButton` 体系）——与 F3.3 同构，全站容器 footer 只许此三型。`强制：评审`

**F9.3 按钮组（ButtonGroup）使用判据** `[MUST]`（用户点名项，四问定序）：

1. 是**互斥视图切换**吗？→ 用 `Tabs variant="segmented"`，**不是** ButtonGroup；
2. 是 **footer 确认对/动作排**吗？→ 平铺 `gap-2`，**禁** ButtonGroup（F3.3）；
3. 是 ≥3 个**同质低频次要动作**挤占工具栏吗？→ 收进 DropdownMenu「更多」，**不**用 ButtonGroup；
4. 是**分裂按钮**（主动作 + 下拉变体，如「保存 ▾（保存并新建…）」）吗？→ **这是 ButtonGroup 唯一合法场景**（主钮 + 分隔 + 下拉钮共用一个圆角外壳）。

> 现状定位：ButtonGroup 仅设计系统画廊 1 处引用，属**休眠原语**——不推广、不清退；首个分裂按钮场景出现时启用，COMPONENTS.md 登记使用场景。`强制：评审`

### F10 横向组合律（跨容器四公理）[MUST]

1. **内距递减律**：容器每降一层、内距收一档——页面 `px-4~6` → 卡片 `px-(--card-spacing)` → 子卡/面板 `px-2~3` → 单元格 `px-2`。外层内距 ≥ 内层。`强制：评审`
