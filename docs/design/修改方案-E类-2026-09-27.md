### 〇之二、本次裁决带来的贯穿性调整：删除全部走三段式

你在 D 项裁定 **「先不删，先在 design system 页标记，我看过后再删」**。

这不只影响 D。**E1 的 5 个零引用死件、E7 的 `shared/ui/` 目录，同属「组件去留」决策**——按同一逻辑都应先标记、你看过再删。因此本方案把三段式**上提为贯穿全方案的总原则**：

```
① 标记（本方案批 1-4 完成，不动任何组件文件）
     └─ registry 记 review-proposal + 设计系统页可视标记
② 审阅（你，在 /app/design-system 上一次性看完所有候选）
     └─ 逐条裁决：delete / merge / keep / rename
③ 清退（批 9 执行，只做你已批准的删除）
```

**收益**：① 删除动作全部可回退（批 1-4 零风险，纯新增标记）；② 你在**一个页面**上看到全部候选及其理由，比看文档快；③ 避免我误删你本想保留的东西。

**唯一例外**：`COMPONENTS.md` 与代码的**登记漂移**（`lint:registry` 现有双向对账）照旧实时修，不走三段式——那不是裁决，是纠错。

## 一、宪法新增条款：§19 组件唯一实现与禁止裸组件

> 写入 `docs/design/PRINCIPLES.md` §19（承接 BCD 方案的 §10.6 三态选型、§10.7 组件 API 约定；§19 是它们的**执行层**）。
> 下列每条都标注 **[MUST]/[SHOULD]** 与**是否有机器强制**。**没有机器强制的 [MUST] 不写进宪法**——这是本方案的硬性自律。

### 19.1 三分目录命名空间 [MUST]

> ⚠️ **本条已于 2026-09-29 按 G 类方案修文**（`修改方案-G类-分层解耦-2026-09-29.md` §2.1/§2.2，裁决 G1–G8 同日落定）：原「唯一命名空间 = `components/ui/`」口径由**三分目录命名空间**承接；原条文所附「ui 原子 / `shared/components/` 跨模块业务 / `modules/<m>/components/` 模块专用」三层放置规则不再由本条承载，回归根 `AGENTS.md` §九 模块放置规范。下文即修文后现行条文。

> **本仓库 UI 组件层有且仅有以下三个目录，目录即层，依赖方向与出口规则按目录判定：**
> 导入一律按文件路径直导（`@/components/ui/<file>` · `@/components/raw/<file>` · `@/components/semantic/<file>`），禁 barrel。

| 目录 | 角色 | 形态约束 | 出口规则（谁能 import） |
|---|---|---|---|
| `components/ui/` | **存量原子组件**（Button/Card/Dialog/…） | 六轴/五轴既成事实，**轴冻结**（§七之十一 裁决 4：无组件立项不加轴）；新组件**不再进入本目录** | 业务面 / semantic 均可消费（现状不变） |
| `components/raw/`（新） | **原语层**：非动作交互元素的具名直通出口 | 直通封装：不套样式基线、无 cva 轴、`type` 默认 `button`、透传全部原生 props | **仅** `components/ui/` 内部与 `components/semantic/` 可消费；**业务面（modules/shared/app）禁入** |
| `components/semantic/`（新） | **语义组件层**：今后新增组件的默认落点 | 内部组合 raw + ui 原子；**props 面封闭**（不透传任意 `variant`/`className`——语义组件是基线变更的隔离层，§七之十一 裁决 3） | 业务面可消费（这正是它存在的意义） |

**出口规则表（R1–R8，`lint:layers` 依赖矩阵）**：

| # | 规则 | 方向 | 违例语义 |
|---|---|---|---|
| R1 | modules/shared/app → `components/raw` | ✗ | 业务面必须经 semantic 或 ui，不得直取原语 |
| R2 | `components/raw` → ui / semantic / modules | ✗ | 原语在最底层，只准依赖 token/lib/原生（防环） |
| R3 | `components/ui` → semantic | ✗ | 原子不依赖上层（防环；ui→raw 见 R4 ✓） |
| R4 | `components/ui` → `components/raw` | ✓ | 原子内部的非动作钮改用具名出口（渐进，非批量） |
| R5 | `components/semantic` → raw / ui | ✓ | 语义组件的唯一实现方式 |
| R6 | `components/semantic` → modules | ✗ | 语义组件不得反向依赖业务 |
| R7 | `components/raw` 内部禁 cva / 基线样式类 | ✗ | 原语保持「裸」（代码审查约定 + 可选 lint 规则，见 G 类裁决 G3） |
| R8 | `components/ui` 新增文件 | ✗ | 目录冻结：新原子件不再进 ui/（红利：ui/ 文件数只减不增） |

- **[MUST]** R1–R6 进 `lint:layers` 机械强制，**落地即 error**（G 类裁决 G3：零存量违例的新目录规则不设 warn 期）；R7/R8 首期作**代码审查约定 + registry 门禁侧校验**（ui 目录文件清单快照，新增即报），二期机械化。
- **[MUST]** 原子层组件**禁止** `import` 任何 `modules/*`（含类型）。违反即分层倒置——既有 `lint:layers` 存量检查口径不变（存量违例按 G 类裁决 G7 随簇收编）。
- 强制：`lint:layers` R1–R6（§四）；R7/R8 代码审查 + registry 门禁侧校验（二期机械化）。

> 引用口径注记：本条仍为**方案级 `[MUST]`（待升格）**，出处为本文档而非宪法（`PRINCIPLES.md` 附录 A.3：§19 暂未入宪，机器强制落地前不入宪；见本文更正五）。

### 19.2 禁止裸组件 [MUST] ★ 你的第 4 条

> ⚠️ **本节路线已于 2026-09-29 整体废止（§七之十一）**。裸原生元素在生产代码重新合法，代之以「三层分层解耦」：动作钮走 `<Button>`、非动作交互元素走具名直通出口（RawButton 一类）、特殊形态立语义组件。下文保留为历史方案原文，**不得按此执行**。

**「裸组件」的可执行定义**（不定义清楚就无法强制）：

> **裸原子控件** = 在 `src/components/ui/` 之外，直接书写的下列 JSX 标签：

| 标签 | 处置 | 替代 |
|---|---|---|
| `<button>` | **禁止** | `ui/button` 的 `<Button>`（含 `variant`/`size`） |
| `<input>` | **禁止** | `ui/input`（或 `ui/native-select` / `ui/checkbox` / `ui/switch` 按语义） |
| `<select>` | **禁止** | `ui/select-field`（表单）或 `ui/select`（组合件） |
| `<textarea>` | **禁止** | `ui/textarea` |
| `<label>` | **禁止** | `ui/label`（+ `ui/field` 组合件） |
| `<table>` | **禁止** | `ui/table` 套件（`check-ui-governance` 已有同规则） |
| `<a>` | **条件禁止** | 站内跳转 → `react-router` `<Link>`；仅 `href` 以 `http` 开头的**外链**允许 `<a>` |
| `<img>` | **禁止** | `ui/avatar`（人像）/ 其他场景登记豁免 |

**明确不禁的**（否则页面写不出来）：`div` `span` `section` `main` `aside` `nav` `header` `footer` `ul` `ol` `li` `form` `h1-h6` `p` `hr` `figure` —— 这些是**布局原语**，它们的**样式**受 A 类「只从 theme 取值」约束，**不受本条约束**。

**豁免机制**：
- 文件 `apps/frontend/design-governance.allowlist.json`，每行 `{ file, element, reason, owner, expiresAt }`。
- **[MUST]** 豁免**只可收窄**：新增豁免行必须在 PR 描述里给出理由，且 `expiresAt` 必填（最长 90 天）。
- **[MUST]** 逾期未处理 → CI 失败（`lint:naked` 会检查 `expiresAt`）。

- 强制：ESLint `design-governance/no-naked-controls`（§四）

### 19.3 组件覆盖率 100% [MUST] ★ 你的第 4 条后半个

> ⚠️ **轴一 PEC 已随 §19.2 于 2026-09-29 废止（§七之十一）**——「页面裸元素清零」不再是目标。**轴二 LU 保留**（逼问每个 ui 组件谁在用，与裸组件路线无关），registry 五态基建不变。下文保留为历史方案原文。

「覆盖率」被拆成**两个可分别度量的轴，各自目标 100%**。不拆开就无法度量。

#### 轴一 · 页面元素覆盖率 PEC（Page Element Coverage）

```
PEC = 1 − (裸原子控件出现次数 ÷ 原子控件总出现次数)
目标 = 100%
```

即 §19.2 清单外**零出现**。度量口径：ESLint 报错数 = 0（豁免清单内除外）。

#### 轴二 · 组件库利用率 LU（Library Utilization）

```
LU = 有真实消费方的 canonical 组件数 ÷ canonical 组件总数
目标 = 100%
```

**这条是反向约束**：它逼问「`components/ui/` 里每一个组件，谁在用？」

为此引入**组件生命周期五态**（登记在 `COMPONENTS.md` / `registry.ts`，是 `lint:registry` 的输入）：

| 状态 | 含义 | 是否计入 LU 分母 | 是否必须在画廊展示 | 是否需消费方 |
|---|---|---|---|---|
| `canonical` | 唯一实现，有真实消费方 | ✅ 计入 | ✅ 必须 | ✅ 必须 ≥1 |
| `standby` | 候选件，**当前无消费方**，零维护成本（源自 base-ui/coss/reui 官方注册表） | ❌ 不计 | ✅ 必须 | ❌ 不要求 |
| `internal` | 仅被其他 ui 组件消费，**不对外导出** | ❌ 不计 | ❌ 免 | — |
| `review` | **待人类裁决**（本方案新增，承接 〇之二 三段式） | ❌ 暂不计 | ✅ 必须（带醒目标记） | ❌ 暂不要求 |
| `deprecated` | 已有替代品，待清退（必带 `expiresAt`） | ❌ 不计 | ✅ 标记 deprecated | — |

> **`review` 态的防滥用条款** [MUST]：`review` **必带 `reviewBy` 日期**。逾期后自动降级为 `deprecated`（带 `expiresAt`）或升级为 `canonical`（此时必须有消费方）。**标记不能变成永久逃避。**

**「真实消费方」的定义**（防止画廊自证）：
> 指 `src/modules/**` 或 `src/shared/**` 中**非测试、非设计系统页**的文件对该组件的引用。

→ 由此，**15 个只被画廊引用的组件自动失格**，必须落进 `standby` / `internal` / `review` 或清退，不能靠画廊"凑数"。

- 强制：`lint:registry` 扩展（§四）——`canonical` 且消费方 = 0 → 失败；`deprecated` / `review` 逾期 → 失败。

### 19.4 变体优先原则 [MUST] ★ 你的第 5 条

> ⚠️ **本节已于 2026-09-29 修订（§七之十一 裁决 4）**：「同一能力第二实现 → 一律统一组件+新增变体」改为「**先判职责**——同职责归并，新职责立语义组件」；原子组件变体轴**冻结**（批 0/0b 已补档位保留为既成事实，新档原则上不再加）。D1/D2/D3 禁令与 className 白名单**维持有效**。下文保留为修订前原文。

> **当同一 UI 能力出现第二处实现，或既有组件被要求呈现新形态时：一律改造为「统一组件 + 新增变体」，禁止在页面/模块内私自改造。**

**禁止的三件事**（这是"私自改造"的可执行定义）：

| 禁止 | 形态 |
|---|---|
| **D1 复制** | 复制组件源码另存新文件（`stats-card` 旁再写 `stat-card`） |
| **D2 视觉覆盖** | `<Button className="h-7 px-2 text-[11px] bg-blue-500">` —— 用 `className` 改写组件**核心视觉** |
| **D3 包裹改写** | 用包裹 `div` + CSS 改写组件内部布局/尺寸 |

**`className` 的合法边界**（D2 的精确化）：

| 允许（定位类） | 禁止（视觉类） |
|---|---|
| `m-*` `mx-*` `my-*`（外部间距） | `p-*` `px-*` `py-*`（内部内边距） |
| `col-span-*` `row-span-*` `basis-*` `grow` `shrink` | `h-*` `w-*` `min-h-*` `max-w-*`（尺寸） |
| `self-*` `justify-self-*` `order-*` | `text-*` `font-*` `leading-*`（排版） |
| `relative` `absolute` `z-*`（调用方定位） | `bg-*` `text-<色>` `border-*` `ring-*` `shadow-*`（视觉） |
| `hidden`/`sr-only`（调用方语义） | `rounded-*` `gap-*`（内部几何） |

**变体轴的封闭词表**（防变体爆炸，只允许 4 个轴）：

| 轴 | 用途 | 封闭值域（示例） |
|---|---|---|
| `variant` | 视觉语义 | 由各组件定义，**≤6 个** |
| `size` | 尺寸档 | `xs` / `sm` / `md` / `lg` —— **全库统一四档，不得自造 `compact`/`mini`** |
| `tone` | 状态色 | `default` `info` `warning` `success` `danger`（见 §19.5） |
| `density` | 密度 | `comfortable` / `compact` |

- **[MUST]** `variant` 超过 6 个 → 重审 API（拆组件或改用 `tone`/`size`）。
- **[MUST]** 新增变体必须在 `COMPONENTS.md` 的组件行内登记该变体名。
- 强制：ESLint `design-governance/no-visual-override`（§四）

### 19.5 状态色唯一映射 [MUST]

> 全库有且仅有一条状态色链路，**分两层**（这是对报告 E3「双轨」的正解，不是二选一）：

```
业务状态（task.status / project.status / run.status …）
    │  ① 业务层映射（知道业务语义）
    ▼

## 四、机器强制：把设计门禁从 grep 升级到 ESLint

### 4.1 为什么必须换工具（这是 E 类能落地的技术前提）

现状：7 个 `check-*.mjs` 是**逐行正则**脚本，**只在 push/CI 跑**（`lint-staged.config.mjs` 在 pre-commit 只跑 eslint）。

**问题**：§19.2（裸组件）与 §19.4（视觉覆盖）**无法用逐行正则可靠判断**——它们需要 JSX 语法树（跨行属性、嵌套、条件渲染）。

**对策**：新建 `apps/frontend/eslint-rules/design-governance.js`（ESLint flat config 插件），承载 3 条 AST 规则：

| 规则 | 拦什么 | 对应条款 | 关键 selector（示意） |
|---|---|---|---|
| `no-naked-controls` | 裸原子控件 | §19.2 | `JSXOpeningElement[name.name=/^(button\|input\|select\|textarea\|label\|table)$/]` |
| `no-visual-override` | `className` 覆盖组件视觉 | §19.4 D2 | `JSXOpeningElement JSXAttribute[name.name='className']` + 宿主名在 ui 组件白名单内 + 值命中视觉类前缀 |
| `no-adhoc-tone` | 页面自造 status→颜色映射 | §19.5 | `VariableDeclarator[init.type='ObjectExpression']` 且值含 `bg-accent-*`/`text-accent-*` 且键含 status 词 |

**这三个额外收益**：
1. **pre-commit 即生效**（解决了 C10）；
2. 有 `// eslint-disable-next-line` 的**精确豁免机制**，比 grep allowlist 更贴代码；
3. 报错带**精确行列 + 可点击文件路径**，比脚本的"文件列表"可修复性高一个量级。

**并存关系**（不推翻既有脚本）：`check-palette` / `check-semantic-classes` / `check-tailwind-arbitrary` / `check-spacing-governance` / `check-icons` / `check-component-registry` **全部保留**（它们做的是文本层检查，正则足够且性能好）。ESLint 只承接**需要 AST 的 3 条**。

### 4.2 新增/扩展脚本

| 门禁 | 类型 | 拦什么 |
|---|---|---|
| `lint:layers` | 新脚本（正则足够：查 `import` 路径） | 原子层 `import modules/*`（§19.1 分层倒置） |
| `lint:duplicate` | 新脚本 | 同名/近义组件（`stat-*` / `*-switcher` / `*-select` / `*-card` 词干碰撞）→ **新增即拦**，存量走 `review` 标记 |
| `lint:registry` **扩展** | 改 `check-component-registry.mjs` | ① 现有双向对账；② **新增**：`canonical` 且消费方 = 0 → 失败；③ `deprecated` / `review` 逾期 → 失败；④ registry 中每个组件必须在设计系统页出现（`internal` 按表豁免） |

```

**「只看待裁决」筛选项**是关键：点击后画廊只显示 `status === 'review'` 的组件，你可以**一屏看完所有候选**，逐条在页面上给结论，比翻文档快。

> **裁决结论的落盘**：你在页面上给结论后，结论写入 `apps/frontend/component-review-decisions.json`（版本化），再由批 9 执行清退。**删除动作永远由已批准的决策文件驱动，不由 AI 自行判断。**
>
> **写回路径的现状与待裁决（2026-09-27 协调方核实）**：`apps/frontend/component-review-decisions.json` **当前并不存在**——它只被上一条、`COMPONENTS.md` 生成器文案与批 4 的裁决面引用；批 4 明记「**只读**、写回未做」。即**「② 人看 → ③ 删」的最后一格仍未接上**：页面上的结论目前仍需人工转达。web 页面**无法自行写版本化仓库文件**，故写回形态必须由人裁决，两个候选：
>
> - **A · 页面导出 + 人工入库**（零后端改动）：页面上给结论 → 「导出决策 JSON」 → 人把文件放进 `apps/frontend/` 并 commit。代价：多一步人工搬运；好处：**不新增任何写接口**，决策必经人的 git 提交（可评审、可回滚）。
> - **B · 后端端点写工作区文件**（自动化）：新增一个受权端点把结论落到工作区磁盘，git 提交仍由人做。代价：**server 侧新增写路径**（须进 `openapi.json` 契约、鉴权与审计），且要防「误操作/AI 直接落删除决策」；好处：一步到位。
>
> **无论 A/B 都适用的三条不变式（须写进实现）**：① **AI 不得代填任何结论**（文件只能由人的动作产生）；② `decision: 'delete'` 必须引用 registry 中**当前且已 `review`** 的条目（`name` 与 `file:` 双匹配）；③ 批 9 只执行文件里**已批准**的项，每项单独 commit 便于回滚。**裁决前不实现任何写回。**

### （二）四项裁决

**裁决 5-1：`size-3.5` 一类「必需连带」升格为迁移通则 —— 采纳。**
`Button` 基线带 `[&_svg:not([class*='size-'])]:size-4`（触屏断点另有 `size-4.5`）。原裸钮的图标若**不带含 `size-` 子串的类**（`h-3.5 w-3.5`、`size={12}`、`size={14}`、`width="14"` 表现属性都属此类），迁到 `Button` 后会被 CSS 归一成 16px（CSS 压过 width/height 表现属性）——**不钉住才是可见几何漂移**。故：

- 判定口径：**为消除「组件基线对子元素的合法归一」而显式钉住子元素尺寸类，不算「改可见样式」，不算风格变更**，是保住无损的必需动作；
- 有争议的是「子元素不得动」这条旧表述——**本轮以本条裁决取代它**：动的边界是「**不得改变渲染结果**」，不是「不得触碰子元素」；
- 先例：`acceptance-detail-page.tsx` 的 `<Plus className="mr-1 size-3.5" />`；本轮三处同型（`onboarding-wizard` / `filter-panel` / `template-manager`）。

**裁决 5-2：`hover:bg-accent` → `subtle` 档的 `hover:bg-muted` 判为可迁 —— 采纳。**
issue 代理就此明确上呈：5 处落轴把 `hover:bg-accent` 交给了 `subtle` 档的 `hover:bg-muted`，**class token 名不同**，按「逐 token **名**等价」的严口径应回退（那样该模块批 6 落轴量归 0）。协调方独立复算 `index.css`：

| token | 亮色 | 暗色 |
|---|---|---|
| `--muted`（`:285` / `:357`）| `240 4.8% 95.9%` | `240 4% 16%` |
| `--accent`（`:287` / `:359`）| `240 4.8% 95.9%` | `240 4% 16%` |

**两态逐值相同**。采信「渲染值等价」而非「token 名等价」，理由不是放宽，而是**方向一致**：`--accent` 与 `--muted` 是**两名同值**的重复注册，收敛掉其中之一**正是 §19.5「单一状态色映射」要实现的事**——把这类迁移判为违规，等于禁止 E 类做它最该做的事。既有同类裁决先例：裁决 7-2 #3（`transition-colors` ≈ `transition-all`，视为等价、允许直迁）。

**连带义务（本次一并登记）**：该等价是**值耦合**，不是语义同一——**任一方被重新着色即破坏等价**。故 `--accent` / `--muted` 两 token 今后**不得单方面改值**；改则须同 PR 复核 `subtle` 档及其全部消费方。（`button.tsx` 的 `subtle` 轴注释已自述此点。）

**裁决 5-3：`Card` 基线 `gap-3` 的 12px 位移 —— 维持不迁。**
三个代理**各自独立**撞上同一阻断：原手写壳根**无内容侧布局类**、且有 **≥2 个直接子元素**时，套进 `Card` 会被基线 `flex flex-col gap-3` 注入 12px 子间间距（原为 block 流、间距靠子元素自身 `pb-*`/`space-y-*`）；而 §19.4 又不许留在 className、铁律也不许为迁移凭空造 wrapper。命中站点：`issue-dependencies-section.tsx:139/148`、`linear-integration-section.tsx:130/137/149`、以及 shared 代理逐模块清点里的一类。
**三代理独立收敛 = 系统性边界，不是个例**。维持不迁。若今后要解，正解是给 `Card` 加一根「子间间距」轴（`gap-3` / `gap-0`），属**新增能力**，须单独立项评审，不在本轮。

**裁决 5-4：`无损` 口径的显式补定义 —— 「档位契约 = 组件基线 + 档位自身，二者均不计漂移」。**
本轮暴露一处此前**未显式定义**的边界：裸 `<button>` 迁入 `Button` 后，**基线**会带来原裸钮没有的 `focus-visible:ring-3` / `active:translate-y-px` / `disabled:opacity-50`；而**档位**也会带来自己的状态类（如 `ghost-danger` 的 `focus-visible:border-destructive/40 focus-visible:ring-destructive/20`）。这些按什么计？
