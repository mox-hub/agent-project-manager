## 4. 问题详情

### P0

#### SEC-01 开发态匿名 admin 可能进入生产
- **证据**：`apps/server/src/common/guards/jwt-auth.guard.ts:66-75` 在 `nodeEnv === 'development'` 且请求无 token 时直接注入 `role: 'admin'` 身份；`apps/server/src/core/config/config.schema.ts:5-7` 中 `NODE_ENV` 默认值为 `development`；`apps/server/.env.production.example` 未声明 `NODE_ENV`。
- **风险**：部署时漏设 `NODE_ENV=production`，所有不带 Authorization 头的请求都以 admin 身份访问非 `@Public` 接口（含 `/admin/*`、工作区创建与备份）。
- **建议**：`NODE_ENV` 改为必填或默认 `production`；开发旁路改为独立显式开关（默认关闭），且启动时在非 development 环境硬性拒绝该开关生效。

#### SEC-02 CLI 派发存在命令注入面
- **证据**：`apps/server/src/modules/cli-dispatch/cli-executor.service.ts:166-176` 中 `shell: built.shell !== false`，未显式声明的 adapter 默认走 shell；`packages/apm-shared/src/cli/adapters/` 下 gemini-cli、grok、codebuddy、qwen-code 将工单正文 prompt 作为 argv 传入；prompt 来源见 `apps/server/src/modules/cli-dispatch/dispatch.service.ts:538,895`。
- **风险**：工单内容含 shell 元字符时，可能在 Runtime 主机上以服务账号执行任意命令。**利用性待复现。**
- **建议**：所有 adapter 统一改为 stdin 注入（claude-code 已是这种方式）；或默认 `shell:false` 并用 `execFile` 逐参传递；补一条含元字符 prompt 的回归测试。

#### SEC-03 工作区隔离依赖隐式信任
- **证据**：`apps/server/src/main.ts:44-56` 原样信任 `x-workspace-id` 头写入 ALS，无归属校验；`apps/server/src/core/database/prisma.service.ts:188-216` 只检查目标库是否已注册；`apps/server/src/modules/team/invite.service.ts:172` 把受邀用户镜像进目标库；JWT 无 `sid` 时 `apps/server/src/modules/auth/auth.service.ts:561-585` 仅按 `sub` 查询。
- **风险**：若某用户曾被镜像进 B 库，持 A 库 token 并伪造 B 的工作区头，可能读写 B 库。**越权可能性为推断，需复现。**
- **建议**：引入显式 WorkspaceMember 校验守卫；JWT 强制携带 `sid`；补跨工作区越权的 e2e 用例（断言 403）。

#### GOV-01 三真相源未纳入版本控制 ⚖
- **证据**：`.gitignore:136-137` 为 `docs/*` 加 `!docs/design/`；`git check-ignore` 命中 PRD、能力清单、`architecture.md`、`modules.md`、决策日志；`git ls-files docs` 仅 17 份。
- **风险**：需求与架构真相无历史、无评审、无法回滚。`check:docs-sync` 只检查已入库的受管文档，对三真相源形同虚设。这与 AGENTS.md 自身"不入库的文档不能作为最高真相源"的论证直接矛盾。
- **建议（需裁决）**：推荐把 `docs/01-需求/`、`docs/02-架构设计/` 纳入版本控制并加入 check-doc-sync 管辖；否则修订 AGENTS.md 的真相源定义，并如实降级文档门禁承诺。

#### ENG-01 PR 门禁存在盲区
- **证据**：`.github/workflows/quality-gate.yml:61,274`：docs job 仅在 docs/、AGENTS.md、README.md、CHANGELOG.md 变更时运行，纯前端 PR 不跑 check-docs-sync；`:55-67` 分类器不识别 `apps/desktop/**`，仅改桌面端时所有 job 跳过且无兜底；`api:audit` 仅在 `.github/workflows/nightly-full-gate.yml:66`，不在 PR 门禁中。
- **风险**：18 个桌面源文件可不经任何检查合并；API 覆盖率棘轮在 PR 中不生效。
- **建议**：补充 desktop 分类；增加无条件执行的兜底 job（至少跑 type-check）；`api:audit` 并入 PR 门禁；docs 检查改为代码变更即运行。

### P1

#### GOV-02 文档数字与版本互相矛盾
- **证据**：AGENTS.md:36/128/146 写"42 能力卡 / 39 前端模块 / 41 后端目录"；实测能力清单约 67 张卡，`apps/server/src/modules` 43 目录，`apps/frontend/src/modules` 42 目录。根 `architecture.md` 仍写 36 目录 / 38 Module 类（v4.0.0）。`docs/02-架构设计/architecture/backend/modules.md` 内部 41 与 39 并存。调研代理报告 AGENTS.md frontmatter 版本（1.3.0）与正文（止于 v1.2.0）不一致，未复核。
- **建议**：用脚本统计生成口径并在 CI 中对账；统一升版；订正 CHANGELOG 中已记录的"AGENTS / architecture 双份生成"不实表述。

#### ARCH-01 模块边界规则形同虚设
- **证据**：`.dependency-cruiser.cjs` 跨模块深挖规则为 `warn`；`check:boundaries` 不在 `quality:gate`（`package.json:23` 与 `:38` 对照）；前端无边界 lint 规则（`apps/frontend/eslint.config.js` 无 `no-restricted-imports`）。实测跨模块深挖导入：server 82 处、frontend 2484 处。
- **建议**：先生成存量白名单，再把规则升为 error 并纳入 gate；前端补 `no-restricted-imports`。

#### ARCH-02 ai-hub 形成循环依赖枢纽
- **证据**：`apps/server/src/modules/ai-hub/ai-hub.module.ts:34-45` 对 9 个模块使用 forwardRef；全仓 22 处 forwardRef；`cli-dispatch.module.ts:33`、`runtime.module.ts:12` 回指 ai-hub。
- **风险**：任一改动波及面大，测试难以隔离。
- **建议**：把 dispatch / context 内核抽成无环底层模块，ai-hub 降为编排层，逐步消除 forwardRef。

#### ARCH-03 CLI 协议"防漂移门禁"名不副实
- **证据**：`scripts/check-cli-contract.mjs` 只校验端点路径存在，不比对 payload；`apps/server/src/core/message-bus/domain-events.ts:5-8` 注释声称有门禁防漂移；server 不依赖 `@apm/shared`，runtime DTO（`apps/server/src/modules/runtime/dto/`）与 `packages/apm-shared/src/runtime/protocol.ts` 为手工双写。
- **建议**：让 server 直接复用 `@apm/shared` 的协议类型；或增加 payload 结构对比脚本并纳入 gate；同步修正该注释。

#### ENG-02 本地 quality:gate 与 CI 口径分叉
- **证据**：coverage 阈值只在 `test:coverage` 生效；server 覆盖率阈值仅约 11%（`apps/server/vitest.config.ts`）；前端 Playwright e2e（10 个 spec）不在任何 CI 中；knip 与 dependency-cruiser 未进入任何 gate。
- **建议**：CI 增加 coverage 步骤并提高 server 基线；e2e 接入 nightly（或 PR）；knip 至少接入 nightly。

#### ENG-03 cli 与 apm-shared 完全不做 lint
- **证据**：两包无 lint 脚本、无 eslint 配置，共 46 个源文件；`pnpm lint`（turbo）跑不到它们。
- **建议**：补配置，与 server / frontend 对齐。

#### ENG-04 TypeScript strict 全部关闭
- **证据**：`apps/frontend/tsconfig.app.json:25-28` 中 strict、noImplicitAny、noUnusedLocals 均为 false，覆盖约 999 个源文件。（前端 type-check 脚本本身正确，使用 `tsc -b`。）
- **建议**：按目录分批开启；先对新增代码强制 noImplicitAny。

#### ENG-05 server 显式 any 泛滥
- **证据**：`: any` 381 处、`as any` 298 处，集中在边界层，如 `project.controller.ts:30`、`issue.controller.ts:17`、`events.gateway.ts:17`。
- **建议**：先为 controller / gateway 的入参补 DTO 类型；再对新增代码开启 no-explicit-any 为 error。

#### SEC-04 OAuth2 state 未签名、无时效校验
- **证据**：`apps/server/src/modules/auth/oauth2.service.ts:230-241` 仅 base64 解码 JSON，代码内 TODO 未校验 timestamp。
- **风险**：可伪造或重放 state，导致登录 CSRF 或账号绑定劫持。
- **建议**：HMAC 签名 + 过期时间 + 一次性 nonce。

#### SEC-05 加密密钥被补零弱化
- **证据**：`apps/server/src/core/crypto/encryption.service.ts:43-56` 在密钥长度不足时 `padEnd(32,'0')`。
- **风险**：短密钥被补零成低熵密钥，集成凭据密文可被穷举。
- **建议**：长度不符直接启动失败；对加密密钥做格式与熵校验。

#### SEC-06 MCP SSE 令牌走 query 参数
- **证据**：`apps/server/src/modules/mcp-server/mcp-server.controller.ts:81-95` 将 token 拼入 endpoint / query。
- **风险**：token 进入访问日志与 Referer。
- **建议**：改用 Authorization 头或 POST 握手。

#### PROD-01 无卡开工（collaboration / environment） ⚖
- **证据**：`apps/server/src/modules/collaboration`（接口协作状态机）与 `apps/server/src/modules/environment` 在全仓无 CAP 能力卡引用，违反 AGENTS.md"未进能力清单不得开工"的硬规则。
- **建议（需裁决）**：补能力卡，或登记为既有卡的切片，二者择一。

#### PROD-02 移动端规划与桌面优先宪法冲突 ⚖

- **建议（需裁决）**：冻结 M 线；或在宪法中明确独立预算与出口判据后再推进。

#### PROD-03 非专业用户原则未机制化
- **证据**：onboarding 步骤（`apps/frontend/src/modules/onboarding/components/environment-step.tsx`、`workspace-root-step.tsx`、`configure-ai-step.tsx`）直接暴露"运行时 / 守护进程 / API Key / Base URL"等术语，无渐进折叠；`apps/frontend/src/components/ui/accordion.tsx` 已存在却未使用。
- **建议**：高级配置项默认折叠；术语换成面向小白的说法。

#### PROD-04 重审结论与代码不符
