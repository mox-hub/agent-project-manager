## 0. 三十秒读懂

你要接手的是 APM 前端（`apps/frontend`）的 **E 类设计治理**收尾工程。前序工作已把「禁止裸组件 / 变体优先 / 唯一实现」所需**能力**（组件变体轴）基本补齐，并落地了第一批迁移。

**最重要的一句话**：这**不是替换工程，是能力补档工程**。实测转化率长期在 **1%–2%** 量级——每 100 个裸控件里只有 1–2 个能真正无损落轴，其余全被「缺档」卡住。**所以你的主要产出不是「迁了多少个」，而是「补了哪几个档、解掉多少处」，以及把卡住的原因量化。**

第二重要：**迁移的唯一验收标准是「渲染结果不变」**。改动一个裸控件时，如果落轴后渲染出的几何/颜色与原来不同，那就是错的——哪怕它「看起来更规范」。为此，为抵消组件基线的合法归一而显式钉住子元素尺寸类（如给图标加 `size-3.5`）**是允许的，且必要时是必须的**。

### 任务 A（P0）：`Button.padding` 轴补 **zero 档** —— 单一缺口解 66 处

### 任务 B（P0，**裁决类，先别编码**）：`Button.size` 轴四档圆角钳位与 §4.5 相抵

- **目标**：拿一个结论，不是拿一个补丁。
- **依据**：§七之六（四）5-②；宪法 §4.5（「按钮**一律** `rounded-md`，不因尺寸降档」）。
- **证据（协调方实测，已复算）**：`xs` / `sm` / `icon-xs` / `icon-sm` 四档写的是 `rounded-[min(var(--radius-md),8px)]`；而 `--radius-md: var(--radius-control)`（`index.css:92`）、`--radius-control: 0.625rem`（`:296`）⇒ **实解 min(10px, 8px) = 8px**，基线 `rounded-md` 是 **10px**。**即这四档的圆角比同族其余档小 2px，原子层自身违反 §4.5。**
- **它卡住了什么（代理自报）**：shared 代理 **26 处** `h-6`/`h-8` 系（`size-6` / `size-7` / `size-8` / `h-7` …）按钮「落不进任何 size 档」的**根因**就是这个钳位。
- **你要做的**：写一份**决策简报**（现状 / 两方案的可见影响面 / 风险 / 建议），**上报人裁**。两方案：(a) 改钳位值使其等于 `rounded-md`——**是动作层的存量变更，有可见影响面**；(b) 维持现状——则 26 处永久不可迁，并须在宪法里给该偏差一条豁免或说明。
- **禁止**：**不要**直接改 `button.tsx` 的钳位值。这是存量视觉变更，必须人批。

### 任务 C（P1）：裸 `<label>` 半 —— 178 处，**三条硬阻断未决**

- **目标**：把 `FieldLabel` 的两轴真正用起来，或判定其不可用并给出替代。
- **依据**：§七之五（二）。
- **证据**：`FieldLabel` 的轴**在批 0 就已补出**（`size` / `variant`），但**一处未消费**。实测 className 形态 Top：

| 形态 | 处数 | 可否轴表达 |
|---|---|---|
| `text-xs font-medium` | 30 | ✅ `size="xs"`（`font-medium` 是基线） |
| `text-xs text-content-text-secondary` | 18 | ❌ **token 不一致**（见下） |
| `text-xs font-medium text-foreground` | 14 | ⚠️ `text-foreground` 是显式设色，`Label` 靠继承 |
| `text-sm font-medium text-muted-foreground block mb-1` | 12 | ❌ `block` 不在 §19.4 白名单内 |
| `text-xs` | 10 | ✅ `size="xs"` |

- **三条硬阻断（必须先有结论，否则整批不可动）**：
  1. **token 不一致**：`variant="muted"` 给的是 `text-muted-foreground`，而实测用的是 `text-content-text-secondary`——**两个独立注册的 token**（`index.css:45` vs `:79`），取值**极近但不等**（亮 `240 3.8% 46.1%` vs `240 4% 46%`）。**差 0.1% 也是可见变更，不得当等价处理**。（对照：`--accent` ≡ `--muted` 是**逐值相同**，那个可以；这两个不行。见待裁 #3。）
  2. **`block` 不在 §19.4 的 className 白名单内**（白名单只有定位类：`m-*` / `col-span-*` / `self-*` / `order-*` / `z-*` / `relative` / `absolute` / `hidden` / `sr-only`）。12 处因此被卡。
  3. **`FieldLabel` 自带 `flex w-fit gap-2 leading-snug …` 布局基线**——从裸 `<label>`（inline）迁过去**不是类级无损**，属**形态变更**。需人裁「接受该基线」还是「另立窄轴」。
- **可以先做的**：`text-xs` / `text-xs font-medium` 两族（**约 40 处**）无硬阻断，可先做，但**须先独立复算这个 40 的口径**。
- **禁止**：`variant="muted"` **不得**用来替代 `text-content-text-secondary`。

## 9. 反面教材（前人踩过的坑，逐条给你省时间）

1. **不要用「看起来更规范」当理由改渲染结果。** 迁移的唯一标准是**渲染不变**。
2. **不要把「子元素不得动」当铁律。** 为抵消组件基线的合法归一而钉住子元素尺寸（`size-3.5`）**是必要的**——不钉住才是漂移。有仓内先例：`acceptance-detail-page.tsx` 的 `<Plus className="mr-1 size-3.5" />`。
3. **不要用 `--amend`**（并发下必炸，见 §3.2）。
4. **不要把别人给的数字当既成事实引用**。上一轮：shared 代理在提交信息里写「手写卡片壳 40 处」，那是从文档**全局口径借引**、**未在范围内复算**的**不可复现数字**。**协调方自己**也把 12 处写成 13 处，被实测纠正。**凡引用必复算；凡计数必写口径。**
5. **不要为迁移凭空造 wrapper div 抵消基线影响**（如为躲 `Card` 的 `gap-3` 而加一层 div）——那是新增结构，不是迁移。
6. **不要在 `warn` 阶段就把违规当「必须马上清」**。2287 条告警是**存量盘点**，不是 2287 个待办——大多数被上面 §7 的 13 条归因合法卡住。**先补能力，再谈清零。**
7. **给组件源码写注释时别写「N 行 / M 处」的先例数。** 已裁决「**删数留结论**」——同型计数在不同口径下不可复现，写进源码即成不可核对的噪声（`ui/card.tsx` 的注释里有这条的说明）。

## 10. 交付定义（DoD）

每一项交付必须同时满足：

1. **渲染等价**：逐处给出「原类串 → 轴组合 → 等价依据」三列证据；等价依据优先用**构建产物**（`dist/assets/index-*.css`）或 **token 定义值**（`index.css`），不用推理。
2. **`pnpm type-check` exit 0**。
3. **`npx eslint` 对改动文件 0 error**（告警不得**新增**）。
4. **测试**：按宪法 **§18.2 不得断言 className**。若原测试断言了类选择器，**改成语义断言**（如 `closest('[data-slot="card"]')` + `getByRole('button')`），先例见 `ef123cec`。
5. **提交**：显式路径 / 无 `--amend` / 信息里写明「改了什么、为什么、口径是什么、剩余多少」。
6. **报告**：附**变更摘要**（范围/类型/影响/同步状态）+ **两项清单**——「已迁移」与「判为不可无损」**都要列**，后者注明命中的 §7 归因编号。**不可无损清单比已迁移清单更有价值**。
7. **数字**：凡报数字，必须能被复算，且**写明口径**。
