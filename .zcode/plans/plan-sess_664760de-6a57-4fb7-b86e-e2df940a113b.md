# APM 成员/团队/工作区重构实施方案

## 0. 总体架构决策（已与你确认 + 我补充的口径）

1. **成员主体统一到 Member**：`User` 仅作认证身份（human 1:1 关联），`Member` 是「成员」唯一主体（human + ai_agent）。`Task.assigneeId`（userId 轨）不做全面迁移，保留 `task-assignee.service` 现有双轨粘合，避免爆炸式改动。
2. **工作区 = 独立目录 + 独立 SQLite**：单后端进程，`x-workspace-id` 请求头 → AsyncLocalStorage → per-workspace PrismaClient 池。注册表存 `workspaces.json`（server 数据目录）。真隔离、切换即时。
3. **邮件**：`MailOutbox` 表落库；配 SMTP（nodemailer）则真发，未配则管理界面查看/复制邀请链接。
4. **团队画布**：本轮做层级视图（现有组件），不引入画布库；`canvasLayout` 字段本轮不加。
5. **AI 授权对象**：项目访问（增强 MemberProjectBinding）+ 工具/MCP/技能白名单（新表 MemberToolGrant）。

## 1. 数据模型变更（apps/server/prisma/schema.prisma）

**Member 增列**：`shortId String @unique`（8 位 crockford base32，创建时生成，`:id` 路由兼容 shortId）、`title String?`（职务）、`description String?`（描述，从 metadata.bio 字段化）、`trustLevel String?` + `trustScore Int?`（从 AppConfig `trust.profile.*` 懒迁移，trust.service 改写 Member 列）、`personalPrompt String?`（个人提示词）、`thinkingLevel String?`（minimal/low/medium/high/max）、`tags Json?`（string[]）、`costRatePerDay Int?`（统计费率，分）。

**Team 增列**：`teamPrompt String?`、`tags Json?`、`updatedAt DateTime @updatedAt`；创始人 = 现有 `ownerId`，响应中聚合 displayName。

**新表**：
- `MailOutbox`（to/subject/body/template/payload/status[pending|sent|failed]/sentAt?/error?）
- `MemberToolGrant`（memberId + scope[cli_tool|mcp_server|skill] + refKey + granted + grantedBy，`@@unique([memberId,scope,refKey])`）
- `TeamInvite` 已有，补 `acceptedAt`；`AppConfig` 新增 `auth.registrationMode`（open，默认）。

**迁移**：按本仓库 SQLite 工作流用 `prisma migrate dev` 失效时的手动路径（db execute + migrate resolve），seed 同步更新。

## 2. 后端实现

**workspace 模块（新）**：`WorkspaceRegistryService`（workspaces.json CRUD、路径校验、初始化：建 data/uploads/logs 子目录 + 复制模板库）；`WorkspaceContextMiddleware`（header→ALS，缺省 fallback 默认工作区，e2e 不带 header 可跑）；**PrismaService 改造为 per-workspace client 池**（保持注入接口不变）；`GET/POST /workspaces`、`POST /workspaces/:id/activate`（admin 守卫）。模板库在 server 构建期生成（db push + 最小 seed：admin 账号 + 基础配置）。

**auth 扩展**：`POST /auth/register`（邮箱+密码+姓名，自动建 User + human Member 含 shortId/handle）；`GET /invites/:token`（Public 预览）+ `POST /invites/:token/accept`（校验登录邮箱匹配 → Member + TeamMember）；`MailService`（Outbox + 可选 SMTP env）；`GET /admin/mail` 发件箱；本地模式（config 消费 APP_MODE=standalone）：`GET /users/search?email=` + `POST /teams/:id/members/direct` 直邀入队。

**member 模块增强**：新字段 CRUD + shortId 生成与路由兼容；`member-card` 聚合新增 shortId/职务/信任等级/标签/提示词存在性/授权摘要；`MemberToolGrant` CRUD（`GET/PUT /members/:id/tool-grants`）。

**team 模块增强**：teamPrompt/tags 读写 + 创始人聚合；`GET /teams/:id/stats/overview`：token 用量（AIUsageLog 真实按成员∈团队日聚合）、活跃热力图（MemberActivity/Mention/TaskActivity 真实计数）、人天成本（活跃天×费率，费率缺失按默认档并标 mock）、成员排行。

**注入链路**（`dispatch.service.buildPrompt` + ai-hub context-builder）：新增 `## Member Instructions`（个人提示词）、`## Team Rules`（成员所在 active 团队 teamPrompt 去重拼接）、thinkingLevel→CLI 映射（claude-code/codex/zcode 各自的推理强度注入方式）；聊天消息 @ 提及 → 被提及成员卡片摘要+个人提示词注入对话上下文。

## 3. 前端实现（全部对齐 design system，新组件在 design-system 页补展示用例）

**新通用组件**：`MentionTextarea`（@ 触发 suggestMentions 弹层，插入 @handle）、`MentionRenderer`（@handle→MemberChip+悬浮成员卡）、`AvatarPickerField`（内置头像集 `public/avatars/*.svg` 12~16 个 + URL 自定义）、`ActivityHeatmap`（CSS grid 热力图，无新依赖）、`TrustLevelBadge`。

**成员页**：列表/卡片补 职务/信任等级/标签/shortId；创建/编辑对话框三 Tab（基础：头像/姓名/职务/信任等级/描述/标签；AI：模型/CLI/思考强度/个人提示词/工具授权；人类：邮箱/关联用户/费率）；详情页补档案字段+shortId 复制+提示词编辑区+「工具与访问授权」区；MemberCardPopover 增强动作行（复制 shortId、注入提示词到 AI 输入、派发任务预置负责人）。

**@ 集成**：任务创建/详情描述用 MentionTextarea+Renderer；命令面板 AI 输入框（command-ai-panel，现有唯一对话入口）接入。

**认证/邀请**：`/register` 页、`/invite/:token` 公开页（预览→登录/注册→接受）、login 页加注册入口与当前工作区标识；团队详情「邀请成员」双模式（邮件邀请→提示去发件箱复制链接；本地模式直接检索用户添加）。

**团队页**：teams 卡片升级（头像/标签/创始人/更新时间/成员数）；team-detail 页签化：成员/项目/提示词/层级视图/统计。层级视图按 角色分组×human/AI 展示成员卡 + 工作流（AIWorkflowDefinition 步骤条只读展示）。统计页签：stat-card + recharts（token 真实）+ 热力图（真实）+ 人天成本表（部分 mock 标注）。

**工作区**：api-client 拦截器统一注入 `x-workspace-id`（localStorage）；FloatingActions 工作区卡真实化（列表/当前高亮/点击切换=写 localStorage+整页 reload/新建入口）；`/app/workspaces/new` 页（名称+目录路径，桌面端 Tauri dialog、Web 端文本输入+校验反馈）→ POST → 自动切换。

**i18n**：新 key 用行级文本插入（避免 locales JSON 重复键问题）；members/teams 硬编码中文顺带增量补 key，不整体重写。

## 4. 测试与质量门

后端 spec：workspace registry/context、register+invite accept 全链路、member 新字段+tool grants、team stats、dispatch prompt 注装断言。前端 vitest：MentionTextarea、AvatarPicker、ActivityHeatmap、register 表单（注意 localStorage mock 需自接内存实现）。存量失败测试（task-page/project-list-page）不碰。每阶段跑 `pnpm quality:gate`。

## 5. 实施顺序（每阶段独立可合入，均含前后端与真实数据链路）

1. **P0** schema 迁移 + seed 更新
2. **P1** 成员模型增强（shortId/职务/信任等级迁移/标签/描述）+ CRUD + 成员卡片 + 前端表单/详情
3. **P2** AI 成员配置（CLI/模型/思考强度/个人提示词/工具授权）+ dispatch 注入链路
4. **P3** @ 提及全链路（组件+任务/命令面板集成+上下文注入+卡片动作）
5. **P4** 注册/邀请/邮件 Outbox/本地直邀
6. **P5** 团队增强 + 统计页签（token/热力图真实、人天部分 mock）
7. **P6** 团队层级视图页签
8. **P7** 工作区（PrismaService 多库改造+模板库+创建页+悬浮卡切换）——放最后，改造横切但接口不变，前置功能在默认工作区先全量交付

## 6. 主要风险

- PrismaService 多客户端改造是最大风险点：保持注入接口与默认 fallback，e2e 不带 header 仍可跑。
- 开发环境全局守卫放行 mock admin，workspace 创建守卫需真实校验。
- trust 档案迁移为懒迁移（首读 AppConfig 回填 Member 列）。
- 邮箱注册默认开放（open），管理员可经 AppConfig 收紧为邀请制。
